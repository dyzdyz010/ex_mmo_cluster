## 0. 结论（v5）

1. **方向不变**：一张页粒度分区表；Scene 与体素分片同表划界、同址、不同进程；World 退出每笔热路径。
2. **两条硬约束**：(i) 绑定组（整棵预制件树、aid 及其槽页，按共享页传递合并）不跨分区；(ii) 模拟岛连同外一圈页属于同一分区，外圈页不可被划走。
3. **跨界靠可恢复的所有权迁移**：持久迁移行 + 成员占用 + 条件决定；源“释放提交”、目标“导入提交”各一笔、恰好一次；所有持久写与所有权变更在 owner 行上 `FOR SHARE` / `UPDATE` 冲突。
   唯一例外是保护区认领（D7-A 时）：各分区投票加阻挡、控制面持久决定、之后才生效——本设计唯一的两阶段提交（§4.10）。
4. **零跨分区通量是条件结论**：依赖 P6 按 Q1 实现与新规则 R-merge（D3）。
5. **近景**：窗口准入保证窗口不跨分区；协议 41 与客户端不改；服务端改 `next_seq`、独立 aid 号源、前驱链、真实积压计数。
6. **远景**多分区下会出错，D5（协议 42 片段化）前所有多分区阶段只测试；S2 用“他分区已发布版本”保证区域完整、陈旧有界。
7. **需用户拍板的产品语义变化汇总在 §9**（12 项），本稿只给推荐。

## 1. 目标与非目标

用户 2026-10-26：“我们的服务器设计是 scene 负责不同区域的场景，可以拆分，只有世界级需要协调的内容才到 world 不是么？为什么现在重活都是 world 在干？”“体素真值从长远来看就是要和 scene 的边界对齐吧？”

**目标**（承接父稿 1–4）：5. 活跃区域互不相接时吞吐随分区数增长，上界是同时存在的岛数；6. 普通编辑（含扣料）World 进程消息数为 0；7. 一个分片崩溃只影响本分区，恢复 = 本流 O(脏页 + 日志后缀)。

**非目标**：halo 与跨分区数值耦合；跨分区原子提交协议（迁移与 D7-A 认领除外，二者各有限定合同）；锁步时钟；单个热点岛的水平扩展；Scene 与体素同进程；跨机器时钟；
跨角色转账（现无此玩法，届时按批准玩法另定）；本稿内定数值阈值。分支 B 是热点岛的解法，不被取代。

## 3. 方案

### 3.1 名词与闭包

- **页**：L0 页（64 m 立方）。**分区**：一组页 + 同址的 Scene 与体素分片。**基础槽**：基础网格把页映射到槽（XYZ 块），槽 → 分区是一张小表；**覆盖行**：迁移过的页、角色的 owner 行。
- **绑定组**（并查集，必须同属一个分区）：一棵预制件树（根实例记录持有整棵树的覆盖页集，父稿 P1）的 home 页 ∪ 全部覆盖页；一个 aid 的 home 页 ∪ 槽页集；共享任一页的组合并，迭代到不动点。
  组关系由页内身份记录派生（M2b 身份定位），不另存可独立修改的第二份组真值。初始化分区表时按组连通分量整体划给一侧（如园可能整批是一个分量，FX2.9）。
- **三类集合**：模拟资格（§3.3）；读取闭包 R(op)（ring、射线、祖链、home 查找、保护判定）；写入闭包 W(op)（目标格、home 的 g=2 / g=3、整树覆盖页、aid 槽页、角色行）。
  **R 与 W 都须在准备阶段核验归本分区**；唯一例外：信标目的地有效性（只读、过期语义见 §5）与保护区登记的版本化只读投影（D7-A）。
- **模拟岛**：期望模拟集（§3.3）按页相邻连通，再并入相交的绑定组，迭代到不动点。约束：岛 ∪ 外一圈 ⊆ 同一分区；**任何岛的外圈页不能被 T1 划出**。
- **执行规则（D9）**：R ∪ W 中缺的页若是冷页且不在任何岛外圈 → 先 T1（成员 = 该页所在绑定组闭包）再本地执行；在他岛或他岛外圈内 → 显式拒绝并报原因。玩家工具与维护入口同一规则。

### 3.2 零通量：条件证明

若 (a) P6 按 Q1 实现（液体只读 `dy ∈ {0,-1}` 与两层侧邻 `world/liquids.ex:344`；辐射遇非模拟页为遮挡；投射物停边界持 ticket；身体 / 拟态接触只在模拟页），(b) 接缝两侧各至少一页非模拟页，(c) R-merge 被接受，
则分区间液体、传导、辐射、燃烧 / 相变邻接效应为零，守恒按分区成立；环境散热按原外部账记。S0 最小反例：Y 向下落、射线穿冷页、边界重开唤醒、拟态 span 跨页、身体接触。

### 3.3 模拟资格：期望与接纳（修订 P6，AX3.2）

- **期望集 S_want**（每分区每拍计算）：玩家模拟半径并集 ∪ ticket ∪ 当前导通发现得到的电路分量页（Q1 ⑤）。
- **接纳（v4 改）**：默认**按页**授予——S_want 中本页及其外圈都归本分区的页才推进；液体、传导、辐射、ticket 过程的计算单元止于已接纳模拟域及本步必要输入（液体：下层与两层侧邻，`world/liquids.ex:344`），
  未接纳页按 Q1 为墙（不流入也不取出），不要求整个水体或整片热区同属一个分区。**唯一的整体授予是 Q1 ⑤ 的电路分量**（已批准的“整页资格、不截断”）：分量全部页归本分区才推进，否则整体冻结。
- **推进者与活性**：分区每拍重算 S_want，把不归己的页作为“未满足需求”上报控制面（派生、不持久）——冷页走 T1，他岛走合并（T2，迁小岛）。控制面串行化合并，每次成功岛数 −1，有限步收敛；
  合并中触发的新合并排队。超出迁移预算或源 / 控制面不可用 → 本次显式失败并记结构化日志；未满足需求每拍照常重报，控制面恢复、源恢复后自然重试；需求满足后的下一拍自动解冻，不需要玩家移动或资格变化来唤醒。
- **R-merge（新产品规则，D3）**：合并完成前接缝页不授资格、被迁小岛在冻结期间不可编辑且物理暂停、玩家受当前窗口 travel 盒约束。依据：Folia “Any ticking region may not grow while it is ticking.”
  “Adjacent regions must eventually merge to form a single region.”（https://docs.papermc.io/folia/reference/overview/ ）——支持先安排所有权后扩张，不证明等待不改变玩法。
- **Q1(c) 的检查对象（D11）**：开关闭合或降温可在不接新线时合成超限分量（`voxel_region/lib/voxel_region/circuit.ex:21-31`）。候选：① 接线时按“潜在连通图”（忽略开关与温度截断）拒绝，
  **潜在图只计玩家放置 / 加工的导体，天然矿脉材料不计**；② 保持当前导通图检查，运行中超限的分量整体冻结并提示。① 下若将来经天然矿脉在运行中合成超限分量，按 ② 处理。
  事实（F3 核实）：现发布目录的 6 种导电材料无世界生成来源；worldgen v2 设计 `docs/10-active/voxel-authority/2026-08-24-worldgen-v2-3d-density-materialization.md:49-50`“矿脉均后置”；旧目录 id 24 名为 CopperOre，天然铜矿是预期内容。
- **ticket 上限（D10）**：合并 / 拆分会让原本合法的过程超限或重获资格，需产品决定。

### 3.6 窗口准入（取代 v2 的“可行走范围收窄”，AX3.8、FX2.7）

- 多分区只支持流送模式（`collision_window_radius_tiles > 0`）。**适用范围**：窗口准入只约束带碰撞窗口的玩家。NPC 身体与其他无窗口实体（意图经 `movement/intent.ex:63-89` 进入、身体是热种子）
  在 S2–S4 多分区阶段**不运行**（只测试范围声明）；进入 Global system 前须给 NPC 等价规则（其所在页及模拟外圈归本分区才可移动、越界停步），S4 前定。“窗口”= 已安装 ∪ 已请求 ∪ 待装（`player.ex` 的 `window_domains` / `requested_window` / `window_pending`）。
- **准入规则**：CollisionStream 只在“新窗口盒 ∪ 其模拟外圈”全部归本分区时才发请求；否则先请 T1，窗口请求等待。等待期间玩家受当前窗口的 travel 盒约束（窗口盒向内收 1/4 tile，`player.ex:2072-2087`）——
  即现行“慢准备时由碰撞行程限制阻止越界”。travel 仍是一个 AABB，协议 41 与客户端不改；已安装窗口在退休前保持来源不变。
- **T1 前置距离 d_T1**（可配参数，S2 实测）：玩家离当前窗口 travel 边缘小于 d_T1 时预发 T1。T1 延迟下界 = 等热提交边界 + 一次切点（`page_cut.ex:179-196`），d_T1 / 步行速度 小于 T1 p99 时玩家会频繁停步。
- 推论：静态两分区之间存在玩家不可进入的带（宽 ≥ 窗口半径 + 模拟外圈），T1 会推移它；S2 只测试阶段可接受，写进 S2 范围。K ≥ 3 的邻区可见性（`authority.ex` 只支持共面两区）在 S4 前改。

## 4. 所有权交接合同（T1 冷页、T2 岛、TC 角色）

### 4.1 行、锁与冲突边界

- PG 行：`voxel_partition(id, incarnation, state ∈ {running, stopped}, node)`；`voxel_base_slot(slot, partition)`；`voxel_owner(key, partition, version, migration)`（key = 页或 cid）；
  `voxel_owner_base(key, stream, cut_limit)`（基线链，§4.4）；`voxel_migration(...)`、`voxel_migration_member(migration, key)`。
- **物化**：写者对无覆盖行的页先在同一事务中 `SELECT … FOR SHARE` 其基础槽行，再 `INSERT INTO voxel_owner … VALUES (key, 槽的分区, 0, NULL) ON CONFLICT DO NOTHING`——值确定，任何插入者结果相同（FX2.3）。
- **权威写**（日志追加、页段写回、角色行写回、前缀发布）：同一 PG 事务内按规范键序 `SELECT … FOR SHARE` 本分区行（`incarnation = 我`、`state = running`）与所写每个 key 的 owner 行（`partition = 我`、`migration` 为空，或为以本分区为 dst 且 `imported_seq` 已落库、尚未 done 的迁移），不符即回滚并返回 `:stale_owner`。
- **所有权变更**（prepare 占用、commit 翻转、abort 释放、化身 bump、槽改派）：同样按规范键序 `SELECT … FOR UPDATE` 再更新。PostgreSQL：FOR SHARE “blocks other transactions from performing UPDATE, DELETE, SELECT FOR UPDATE or SELECT FOR NO KEY UPDATE on these rows”（explicit-locking，已核实）。
- **错误分类**（FX2.4）：`deadlock_detected`（40P01）、`serialization_failure`（40001）→ 重试整笔，未确认、未广播；只有加锁后校验失败（`:stale_owner`）才证明本进程是僵尸 → 停止进程。
- 正常运行中旧写者不会撞拒绝：迁移成员在 prepare 前已冻结，翻转只发生在源的合法提交边界；拒绝只拦僵尸。成本（1 + k 个行锁读）S2 实测。仓内参照 `data_service/lib/data_service/body_store.ex:45-46`。

### 4.2 迁移状态机与决定守卫（AX3.3、A3-B1）

迁移行 `voxel_migration(id, kind, src, src_incarnation, dst, state ∈ {planned, prepared, committed, done, aborted}, seal_seq H, base_cut B, frozen_at F0, released_seq, imported_seq, open_at F1, unfrozen_seq, stock_j)`。
**决定状态**只有 committed / aborted 两种结局；**完成事实** `released_seq`（源）与 `imported_seq`（目标）彼此独立，任意先后，第二个落库时置 `done`。

| 转移 | 执行者 | 同一 PG 事务内的守卫与动作 |
|---|---|---|
| → planned | 控制面 | 插迁移行（id 幂等）与成员；成员 = W / 岛的绑定组闭包（T2 另含岛外圈） |
| planned → prepared | 源 | 前置（回合内、无 PG）：冻结成员，记 H = 当时 `state.seq`、F0，发封口（§4.5）；等**第一个覆盖 H 的已发布切点 B**（若当时有进行中的切点且其号 < H，待其发布后再开一个，`page_cut.ex:178,193`）。事务：按 §4.1 **物化成员 owner 行**；源分区行 `incarnation = src_incarnation ∧ state = running`；`UPDATE voxel_owner SET migration = m WHERE key ∈ 成员 AND partition = src AND migration IS NULL` 且**受影响行数 = 成员数**（排除同页重叠迁移）；`prefix(src) ≥ B`；记 H、B、F0 与成员存量 `stock_j`；`WHERE id = m AND state = 'planned'`。任一不符 → 回滚、读迁移行 |
| planned → committed（**代为翻转**，源已 stopped） | 控制面 | 只豁免“活源 prepare 与实际释放”，**其余守卫与 prepared → committed 相同**：目标 `running`、两端已应用目录摘要行相等（源取其停止时的摘要）、成员行数 = 成员数、`version + 1`、写基线链；另加：源 `state = stopped` 且化身已 bump、`prefix(src) ≥ 源流最后一笔`、源满足停止前置条件（§4.7）、成员先按 §4.1 物化且 `partition = src AND migration IS NULL`；H = B = `prefix(src)`；`state = committed`、`released_seq = 0`（空释放） |
| prepared → committed | 控制面 | 锁源 / 目标分区行：`src.incarnation = src_incarnation ∧ running`，目标 `running`；锁两端已应用目录摘要行并要求相等；成员 `partition = src AND migration = m` 行数 = 成员数；翻转为 `partition = dst, version + 1`、写基线链 `(src, B)`、保持 `migration = m` 至 done |
| committed：记释放 | 源 | 释放提交 R_m（§4.3）与 `UPDATE … SET released_seq = R_m, state = CASE WHEN imported_seq IS NULL THEN 'committed' ELSE 'done' END WHERE id = m AND state = 'committed' AND released_seq IS NULL`；若本事务使 state 变为 done，同事务 `UPDATE voxel_owner SET migration = NULL WHERE migration = m` |
| committed：记导入 | 目标 | 导入提交 I_m（§4.3）与 `UPDATE … SET imported_seq = I_m, open_at = F1, state = CASE WHEN released_seq IS NULL THEN 'committed' ELSE 'done' END WHERE id = m AND state = 'committed' AND imported_seq IS NULL`；若变为 done，同事务清本迁移占用。**导入后目标即可写成员**（§4.1 允许 `migration = m` 且已导入），但占用保留到 done |
| planned / prepared → aborted | 控制面 | `UPDATE voxel_owner SET migration = NULL WHERE migration = m`——**只清本迁移的占用** |
| aborted：记解冻 | 源（曾冻结时） | 解冻提交 U_m（§4.3）与 `UPDATE … SET unfrozen_seq = U_m WHERE id = m AND state = 'aborted' AND unfrozen_seq IS NULL` |
| 化身 bump（故障转移） | 控制面 | 该源全部 planned / prepared 置 aborted，`migration = NULL WHERE migration IN (这些 id)`，`unfrozen_seq = 0`（冻结只在旧化身内存，随之消失；新化身从 PG 恢复，不需解冻提交） |

- **再次迁移门槛（A4-N1）**：成员占用只在 `done` 时清除，而 prepare / 代为翻转都要求成员 `migration IS NULL`——**前一迁移的释放完成前，成员不能再迁**。源崩溃时由恢复后的新化身执行释放（见下），所以门槛不会永久卡住；释放被拖延时只延迟“再迁”，不影响目标使用成员。
- **源不自行解冻**；结果不明一律读迁移行，条件更新受影响 0 行即重读。恢复扫描：源 → 自己为 src 的 prepared（保持冻结）、committed 且 `released_seq` 空（做释放）、aborted 且 `unfrozen_seq` 空（做解冻）；
  目标 → committed 且 `imported_seq` 空（做导入）；控制面 → planned / prepared 推到决定。两个完成事实互不依赖，任何先后与重复都收敛到 `done`。
- **planned 期间**的冻结只在内存，源崩溃即消失，无不可逆效果。
- **T1 延迟**：成员已被前缀覆盖时 B 立即可得（`page_cut.ex:188-200` 对已覆盖 seq 直接返回）；否则 ≥ 一次切点。
- **T2 冻结时长** = 等热提交边界 + 到 B 发布 + 决定 + 导入。候选优化（S3）：目标预装源已发布版本 C0，导入时补装**相对 C0 的完整差异**（AX1.2），作可测优化，不作保证。

### 4.3 三个时点与三笔提交（AX3.4、AX3.7、A3-B2）

- **三个时点分开**：**封口序号 H**（冻结回合的 `state.seq`，只用于订阅封口与续订）；**基线切点 B**（覆盖 H 的第一个已发布切点，B ≥ H，只用于存储可见性）；**冻结区间 [F0, F1]**（F1 = 实际开放步进的时刻）。
  成员自 H 起冻结、不再被写，所以它们在 B 的可见版本等于 H 时的状态——这是 H 与 B 之间唯一的映射，导入与续订不混用二者。
- **释放提交 R_m**（源流一笔真实事务）：**只移除带迁移标记 m 的冻结表示**——prepare 时源把成员页、角色与被迁岛的流级实体标记为“冻结于 m”（流级实体的标记随其持久行落库），R_m 只删这些；加上 §4.2 的再迁门槛，R_m 不可能触及之后再迁入的同键状态（那时 m 必已 done）。只写流级行，不写成员页（已非 owner）。源故障转移后，新化身从 PG 装入时跳过不归己的成员页，并对带 m 标记的流级实体执行 R_m。
- **导入提交 I_m**（目标流一笔真实事务）：取号 `I_m > max(B, 成员最后 seq)`（§6.2）；按基线链 `(src, B)` 装入成员、加入流级实体、成员页全部标脏；确定 F1 = 本提交的开放时刻并把在途过程时间锚点后移 `F1 − F0`，
  平移量随 I_m 持久，回放得同值、不再平移；**提交后同一回合即开放意图与步进**（不等订阅者，F3-3.5）。于是无任何玩家提交时 `state.seq` 也已前进，按现有规则开切点、发布。
  导入提交之后、首次步进之前若目标重启，重启间隔按现行重启规则处理（与迁移无关，不额外平移）。
- **解冻提交 U_m**（aborted 后，源流）：时间锚点后移 `解冻时刻 − F0`，随 U_m 持久、只做一次；恢复成员的意图接纳与步进。
- **存量记账**：迁移行的 `stock_j`（prepare 时源测；代为翻转时由目标在导入提交中测并写入）。全局审计 = 各流已发布账 + `done` 迁移的 `stock_j` 进出对消。
- **恰好一次**：每笔提交与其完成事实同库同事务；重复请求读迁移行后返回同一 seq。

### 4.4 持久化：流、基线链、可见版本、GC

- 流 = 一个分区的日志流；日志、页段、角色行、流级行都带流 id；前缀表主键 `(cv, 流 id)`；残留清理只删本流 `cut_seq > prefix(本流)`（现 `page_store.ex:35-42` 按 cv，须改）。
- **基线链**：翻转时把源对每个成员的可见来源整体传给目标——源自己的 `(src 流, B)` 加上源尚未被自写覆盖的继承链。页段是 (段, 子块) 多行，**可见版本按段取 max**：
  max{ 本流 `cut ≤ prefix` 的行 ∪ 链中每个 `(流, cut_limit)` 下 `cut ≤ cut_limit` 的行 }。只引用已发布版本，他流未发布残留永不可见；跨迁移同页 seq 单调（§6.2）保证 max 正确。
- **链的截断**：导入提交把成员页全部标脏；某页在本流写回并发布后，删除该页的链（按页、随常规限速写回摊开，FX§3）。再导出时若链未截断，原样传递。
- **I4**：源对某页无任何可见版本时，基线记显式 `never_edited`；“新 owner 下无行”不推出从未编辑。
- **两种授权**（AX3.3）：权威写按 §4.1；**退休本流历史**（删本流 ≤ 前缀的日志、自有页低于可见版本的段行、已迁出页且**不被任何基线链引用**的段行）在同一事务里对相应 owner 行取 `FOR SHARE` 并检查链引用，与翻转写链互斥。
- **一致读取**：分片先登记新化身（bump）再在一个 REPEATABLE READ 事务里读本分区 owner 行、基线链、本流行、前缀与后缀（FX2.8）。多分区组合根只支持 PG 后端。

### 4.5 跨源订阅屏障（AX3.5）

1. **封口**：源在冻结成员的同一回合（H 已提交、H 之后的号未产生），对每个将迁走的订阅者经其 CanonicalFeed 发 `{:handover, m, H}` 并退订——同源到同目标有序（Erlang “if an entity sends multiple signals to the same destination entity, the order is preserved”，已核实），封口恰在 H 与其后继之间。封口不等切点发布；B 只在存储层使用。
2. **消费边界**：CollisionStream 把封口作为普通事件进入自己的 FIFO（与 delta 同序、同 pending 保留）；Scene / Player **消费到**该事件时才停止接受源 delta、等待决定。前驱不因控制消息提前改写。
0. **续订保留下限**（v5 统一，A4-N2）：每个未收口的交接在其续订基点处钉一个保留下限——源钉在 H（从封口起到决定后被封订阅者回接或超时），目标钉在 I_m（从导入起到被迁订阅者接上或超时）。下限同时约束内存保留事务的退休（`world/page_cut.ex:259` 退休 `seq ≤ 已发布切点`）与日志渐进删除（`data_service/lib/data_service/voxel/page_store.ex:153`）：只退休 / 删除低于全部下限的部分。下限只在内存、随超时放开；进程重启时被封订阅者已随源 DOWN 断开，不需要持久。下限放开后到达的续订一律显式 `cursor_expired` → 调用方走既有 `canonical_snapshot_and_subscribe` 显式整窗重取并计数，不静默跳到当前 seq。
3. **目标续订（v4 简化为一阶段，F3-3.5）**：I_m 提交后即开放写入；目标保留下限钉在 I_m（第 0 条）。`subscribe_handover(m, H)` 校验迁移 id 与 H，回复“源封口 = H，首笔 = I_m”，
   从 I_m 起按序补发全部保留事务（含开放写入之后的已确认事务），**不以目标当前 seq 作续订点**；超时后按第 0 条处理。
   正确性：H 之后到 I_m 之前成员页未被任何流写过（源冻结、目标未导入），被迁订阅者的窗口 ⊆ 被迁岛 ⊆ 成员（§3.6），所以“消费到 H + 从 I_m 起补发”无遗漏。
4. **前驱**：每笔提交在日志中记录本流前驱 seq（权威流派生，不为每个消费者维护可写水位）；Player 消费封口后期望“首笔 = I_m”，之后按 I_m 的流前驱链校验。
5. **失败**：源在封口前崩溃 → 现行源 DOWN 即停（`collision_stream.ex:73-75`）→ 会话显式失败重连；abort → 订阅者对源以 `subscribe_handover(m, H)` 自续：源的保留下限钉在 H（第 0 条），从 H 的后继起按流前驱链补发（H 与 B 之间其他岛的提交、解冻提交 U_m 都在其中），前驱链从 H 连续接上；若源在此期间重启或下限已超时放开 → 显式 `cursor_expired` → 整窗重取；在途窗口请求遇冻结 → `{:error, :migrating}`，决定后向新 owner 重发。
6. 多分区阶段不运行 Replica、不支持非流送 Scene（其 `baseline_transaction_seq` 共同基线守卫 `collision_updates.ex:171-172` 不适用跨源；流送路径该字段为 nil）。远程信标传送走 TC + 目标新窗口准备（`player.ex:1431-1441`），不走本屏障。

### 4.6 角色交接与失败收敛（AX5.1、AX3.7）

顺序：Scene seal → 取消施法、等 `body_detach`（旧热量先收口）→ 身体最后保存（`BodyStore.save`，旧 `session_epoch`）→ TC（或随 T2）：源发布覆盖该 cid 的切点 → prepared → committed → 目标导入 →
`WorldServer.Session.commit_transfer` → 目标 `BodyStore.claim`、Player 激活。**收敛规则**：TC 未 committed 前任何失败 → 角色与账留源，Session 移交中止（现 M4a 准备失败语义）；TC committed 之后任何失败
（Gate 断开、Session 提交失败、claim 失败）→ 会话关闭，玩家重连时**在角色行当前 owner 分区登录**，无需再迁移。身体的 `session_epoch` 与分区化身是两个合同。
**换分区登录**：角色行仍在下线时的分区 → TC；该分区运行中则正常迁移；已停止 → 控制面代为翻转（§4.7）；故障中 → 待故障转移完成，期间登录显式失败（D2）。

### 4.7 分区生命周期（FX2.5、FX2.8）

- **启动**：控制面 bump 化身并置 `running`、指定节点；分片先登记再读快照（§4.4）。
- **停止前置条件**：无已接纳模拟页（岛已迁出或冻结过程已按 Q1 冻结且不属任何岛）、流级瞬态集（在飞投射物、拟态、待交付）为空或已随 T2 迁出、无未决迁移。
- **停止 / 退役**：满足前置条件 → 分片停止接纳 → 发布全部（前缀 ≥ 最后一笔）→ 控制面置 `stopped` 并 bump 化身（封住僵尸）。退役 = 对其全部覆盖行（页与离线 cid）做迁移 + 把其基础槽改派给继任分区（槽行 `UPDATE`，与写者对槽行的 `FOR SHARE` 冲突）。
- **代为翻转**：对 `stopped` 分区按 §4.2 单列转移由控制面直接 committed（空释放）；其余情况必须源 prepare。离线角色的换分区登录、退役时的覆盖行迁移都走这条。
- **故障转移**：bump 化身（同时中止其未决迁移，§4.2）→ 在新节点启动。

### 4.8 故障

| 故障 | 行为 |
|---|---|
| 分片崩溃 | 本节点重启、按 §4.4 恢复；期间该分区意图显式失败、其 Scene 停 Tick；其他分区不受影响 |
| 节点崩溃 | 故障转移；会话断开重连 |
| 僵尸（与控制面失联、仍连 PG） | 下一笔权威写被拒并自停；**此前它仍可能向本节点读者供旧快照**，读不受化身保护；会话随故障转移关闭 |
| 控制面停机 | 本分区内闭合的编辑与模拟照常；T1 / T2 / TC、登录、移交、目录发布、保护区认领显式失败或停在原状态；玩家在窗口 travel 盒内停步 |
| PG 死锁 / 串行化失败 | 整笔重试，不算僵尸 |
| 迁移任一步失败 | 按 §4.2 唯一持久决定收敛 |

I1 ← §4.1 冲突边界 + §4.2 守卫；I2 ← 冻结在合法提交边界、基线只引已发布版本；I3 ← §4.4 可见规则 + §6.2 单调；I4 ← 显式 `never_edited`；I5 ← §3.1 R / W 准备核验 + 父稿 P4 复核。

### 4.10 保护区认领的两阶段提交（D7-A，A3-B3、A4-N3）

本设计唯一的跨分区原子提交，只在 D7 选 A 时存在。用**简单拓扑互斥**保证投票有效，不建通用事务框架。
- **登记**（控制面，PG）：`protection_region(id, rect, holder, state ∈ {pending, committed, aborted, released}, version)`（version 每次状态变化 +1）；`protection_participant(region, partition)`；`protection_vote(region, partition, vote)`。
- **发起**：控制面一事务——检查与全部 pending / committed 区域不重叠、每持有者数量；**参与者集合 = 此刻全部 running 分区**写入 participant；存在既未运行又未退役的分区 → 直接 aborted（显式“分区不可用”）；写 pending。
- **拓扑互斥**（pending 期间）：控制面拒绝或排队以下操作，直到该认领决定——成员页落在该矩形列内（x/z 矩形 × 全部 Y）的迁移决定（prepared → committed、代为翻转）、改派列内基础槽、启动 / 停止 / 退役分区。
  于是列内页的归属与参与者集合在 pending 期间不变，“参与者全部 yes”在决定时仍覆盖全部列内页。故障转移不能被互斥（崩溃不可阻止），但阻挡与投票在同一持久提交里（下条），新化身回放即继承，票仍有效。
- **投票**：参与者在合法提交边界做一笔本流提交，PG 事务内先 `SELECT … FOR SHARE` 认领行并要求 `state = pending`：复核本分区拥有的列内页有无他人占用（`world/claims.ex:84-93` 同一判据）；
  无 → 记录**写入阻挡**（矩形内非持有者的新编辑显式拒绝“认领确认中”）并投 yes；有 → no。阻挡、投票行与该提交同一 PG 事务；认领已非 pending 时整笔回滚，**迟到的 prepare 不会在 aborted / released 后装上阻挡**。
  阻挡不改 holder、不重建热域、不唤醒液体、不广播保护投影。
- **决定点**：控制面一事务 `SELECT … FOR UPDATE` 认领行（与投票的 FOR SHARE 互斥）——participant 全部 yes → committed；任一 no 或超时 → aborted。version +1。唯一持久决定。
- **生效（按版本幂等）**：各分区把“已应用保护版本”记在本流全局行；读到决定后在提交边界一笔提交：仅当该认领 version > 已应用值时应用——committed → 装入保护投影（今日 `commit_protection` 的全部效果，`world/claims.ex:98-110`）并撤阻挡；
  aborted → 撤阻挡。重复通知、重启回放都按版本跳过。物理只在决定之后变化，从不补偿撤销；各分区生效时刻不同，因分区间无物理耦合（§3.2），不产生跨分区不一致。
- **恢复**：分区重启从本流恢复阻挡与已应用版本，补做已决定未应用的；控制面重启把 pending 推到决定（超时 aborted）并解除拓扑互斥。认领请求的回复等到决定后返回（有超时）。
- **释放**：无需复核，控制面一事务置 released、version +1，各分区按版本在提交边界移除投影。

## 6. 序号与身份（AX3.6）

### 6.1 两个号源，各自合同

- **提交号 seq**：一笔事务一个。45 处 `seq + 1` 中，凡表示“本笔将取得的提交号”的（回执 seq、实例 birth、保护区 id、`tools.ex:495` 世代、`production.ex:48-51` 骰子种子）改读 `state.next_seq`；
  `log_projection.ex:39` `iterator_from(have_seq + 1)` 是游标下界，不改（FX§3）。
- **附件号 aid**：一笔零到多个（`prefabs.ex:463-470` 每组一个、`parcel.ex:107-110` 批量）。改为本流独立的 aid 号块，按需逐个取；不再用 `max(serial, seq) + 1` 与 seq 耦合（块分配后耦合会跨入他流号段）。
- **前驱链**：每笔提交在日志行记录本流前驱 seq；`collision_updates.ex:256`、`player.ex:1830` 改为校验前驱，保留漏消息检测。**积压**：`page_cut.ex:118` 改为本流已提交未发布的事务计数。
- **K = 1 等价口径**：seq 逐项相等（单块时号仍连续）；aid 数值会变，只验“唯一、引用一致、回执与实际提交一致”。客户端只按相等比较 aid（`VoxelDamageState.cpp:176-177`），不受影响。

### 6.2 号块：PG 计数行（K ≥ 2 启用）

- 每类号一行 `voxel_number(cv, kind, next)`；领块 = `UPDATE … SET next = next + n WHERE cv AND kind RETURNING next - n`，**提交后才使用**。并发领块在该行上串行：READ COMMITTED 下后到者“will wait for the first updating transaction to commit or roll back … attempt to apply its operation to the updated version of the row”
  （https://www.postgresql.org/docs/current/transaction-iso.html ，已核实），故各块不相交、按提交顺序递增。不用 sequence（CACHE > 1 时跨会话可乱序，AX3.6）。重启丢弃未用块尾，前驱链不受影响。
- 承诺：全局唯一、流内单调、同页 / 同角色跨迁移单调；**不承诺跨流实时有序**。
- **导入取号**（T1 / T2 / TC 都适用）：采纳 F 原规则——`max(state.seq, B, 成员最后 seq) + 1`（B 为基线切点，≥ 封口序号 H） 若仍在本流已领块内则用之，否则领新块（新块必大于此前全部已领块）。v2 以“可能落进他流块”拒绝该规则是误读（AX1.5）。
  Lamport IR2(b)：“sets Cj greater than or equal to its present value and greater than Tm”（CACM 21(7) 1978 p.560，已核实）。
- **首次启用**：计数起点 > max(现 seq、`attachment_serial`、全部已发 seq 派生身份)。
- 父稿“新格式不再把全局 seq 当跨区唯一键”在此修订为：保留 seq 派生身份、由块保证唯一。备选（D6）：每分区连号 + 命名空间身份（实例 id、世代进协议）。

## 7. 远景（AX1.4、AX3.9、FX2.10）

- **精确入口（事实）**：`VoxelLodWorld.cpp:1634` 只在 `OnlyRegion` 分支进入 `:1637` 区域 seq 守卫（实时 `ApplyLogTransaction` 在 `:1603` 传 nullptr，`:1745` stash 重放才传区域）；
  `VoxelRegionFetcher.cpp:66` 按区域头 seq 补日志拒旧、`:81` 整区替换；overlay 订阅游标 `World.AppliedSeq`（`VoxelM1Client.cpp:906`）；`VoxelIntentLedger.cpp:46` 以 `ResultRef <= AppliedSeqAtSubmit` 判提交前已摄入。
  近景 canonical 来源（`collision_stream.ex:85`）不带该游标。
- **推断**：多流号段交错时，区域补日志按单一头 seq 会丢他流事务；全局 AppliedSeq 若混入他流高号，会使 overlay 补尾跳过、IntentLedger 误判已摄入。
- **S2–S4 处理（可执行、不改格式）**：overlay 订阅只连本分区流（AppliedSeq 只含本流号）；远景区域载荷 = 本分区页在线值 + 他分区页在 PG 的**最新已发布版本**（只读、不影响任何写结果），区域完整、内容真实、
  **不保证有限陈旧**（他流热提交 / 写回可延迟，且客户端只在重取时刷新）；头 seq 取本流。明列为已知不足，验收不覆盖远景。不进青岚。
- **S5（协议 42）冻结项**：片段 `(level, L0 页)` 与片段版本（跨迁移单调）；完整 / 增量 / 删除；守卫移到片段级；首次未知片段的呈现；初取与订阅屏障；缓存身份与旧缓存失效；ring、structure、树冠与实例元数据归属；
  聚合 owner（Replica 或 CollisionStream 二选一）；近景与远景不共享可写全局水位。
