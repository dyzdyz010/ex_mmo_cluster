## 3. 方案

### 3.1 名词与闭包

- **页**：L0 页（64 m 立方）。**分区**：一组页 + 同址的 Scene 与体素分片。**基础槽**：基础网格把页映射到槽（XYZ 块），槽 → 分区是一张小表；**覆盖行**：迁移过的页、角色的 owner 行。
- **绑定组**（并查集，必须同属一个分区）：一棵预制件树（根实例记录持有整棵树的覆盖页集，父稿 P1）的 home 页 ∪ 全部覆盖页；一个 aid 的 home 页 ∪ 槽页集；共享任一页的组合并，迭代到不动点。
  组关系由页内身份记录派生（M2b 身份定位），不另存可独立修改的第二份组真值。初始化分区表时按组连通分量整体划给一侧（如园可能整批是一个分量，FX2.9）。
- **三类集合**：模拟资格（§3.3）；读取闭包 R(op)（ring、射线、祖链、home 查找、保护判定）；写入闭包 W(op)（目标格、home 的 g=2 / g=3、整树覆盖页、aid 槽页、角色行）。
  **R 与 W 都须在准备阶段核验归本分区**；唯一例外：信标目的地有效性（只读、过期语义见 §5）与保护区登记的版本化只读投影（D7-A″）。
- **模拟岛**：期望模拟集（§3.3）按页相邻连通，再并入相交的绑定组，迭代到不动点。约束：岛 ∪ 外一圈 ⊆ 同一分区；**任何岛的外圈页不能被 T1 划出**。
- **执行规则（D9）**：R ∪ W 中缺的页若是冷页且不在任何岛外圈 → 先 T1（成员 = 该页所在绑定组闭包）再本地执行；在他岛或他岛外圈内 → 显式拒绝并报原因。玩家工具与维护入口同一规则。

- **所有权半径 r_own**（每个玩家）：模拟半径 + 外圈；D13 ② 时取 max(模拟半径, 窗口半径) + 外圈。**期望集 S_want**（每分区每拍计算）= 本分区玩家 r_own 并集 ∪ ticket ∪ 当前导通发现得到的电路分量页（Q1 ⑤）。

  未接纳页按 Q1 为墙（不流入也不取出），不要求整个水体或整片热区同属一个分区。**唯一的整体授予是 Q1 ⑤ 的电路分量**（已批准的“整页资格、不截断”）：分量全部页归本分区才推进，否则整体冻结。
- **所有权前置（v6，取代 v5 的 d_T1 与窗口准入）**：分区另算**预取集** = 本分区玩家以 r_own + d_pre 为半径的页并集。其中不归己的冷页（不在任何岛及其外圈）立即计划 T1：目标先跟随（§3.6），追平后领导权转移（§4.2）。d_pre ≥ v_max ×（T1 从计划到翻转的 p99）+ 一页，S2 实测定参。
  于是正常运行下玩家到达之前 S_want 已归本分区，过界不等所有权。T1 成员是冷页，停写时 H 即源当前 seq，跟随早已追平，T1 ≈ 一笔源提交 + 一笔目标提交。
- **提前合并（v6，取代 R-merge，删除 v5 D3 规则）**：两个岛的“岛 ∪ 外圈”之间页距 < d_merge 时，控制面计划把**较小岛**（成员页数少者，并列按分区 id）整体 T2 到较大岛所在分区：目标先跟随整个小岛的全部成员（不只边界带），追平后领导权转移（§4.2）。
  d_merge ≥ 2 · v_max ·（整岛预拷贝 p99 + 交接 p99）+ 一页（两群相向，相对速度按 2 · v_max），S3 实测定参。合并后不立即拆分；拆分只在 S4 动态拆合中以 d_split > d_merge 滞回进行。
  依据：Folia 的“merge radius”不变式（区域拥有其每个 chunk 合并半径内的全部位置，“guarantees that the region is not close to another region”）、“tick 中不得扩张”与“初始持有边界外缓冲”；BigWorld 把迁移边界“artificially increased (by about 10 metres) to avoid hysteresis”。原句见“依据”。
- **推进者与活性**：分区每拍重算 S_want 与预取集，把不归己的页作为需求上报控制面（派生、不持久）——冷页走 T1，他岛走提前合并（T2，迁小岛）。控制面串行化合并，每次成功岛数 −1，有限步收敛；合并中触发的新合并排队。
  未满足需求每拍照常重报，控制面或源恢复后自然重试；需求满足后的下一拍自动接纳，不需要玩家移动或资格变化来唤醒。
- **合并迟到（事故尾部，不是产品规则）**：若两岛外圈相接时合并尚未翻转（延迟超出包络，或控制面 / 源 / 目标故障），接缝页暂不授资格（按 Q1 为墙：液体不流过、热绝热）；D13 ① 下玩家移动与碰撞照常（窗口由跟随页供数），D13 ② 下表现为现行慢准备停步。
  记结构化日志 `merge_late`（岛、时长、原因）；预取 T1 未及时完成同样记 `prefetch_late`。S3 验收要求二者为 0（§8）。
- **Q1(c) 的检查对象（D11）**：开关闭合或降温可在不接新线时合成超限分量（`voxel_region/lib/voxel_region/circuit.ex:21-31`）。候选：① 接线时按“潜在连通图”（忽略开关与温度截断）拒绝，
  **潜在图只计玩家放置 / 加工的导体，天然矿脉材料不计**；② 保持当前导通图检查，运行中超限的分量整体冻结并提示。① 下若将来经天然矿脉在运行中合成超限分量，按 ② 处理。
  事实（F3 核实）：现发布目录的 6 种导电材料无世界生成来源；worldgen v2 设计 `docs/10-active/voxel-authority/2026-08-24-worldgen-v2-3d-density-materialization.md:49-50`“矿脉均后置”；旧目录 id 24 名为 CopperOre，天然铜矿是预期内容。
- **ticket 上限（D10）**：合并 / 拆分会让原本合法的过程超限或重获资格，需产品决定。

### 3.6 跟随页、窗口来源与传送（v6，取代 v5 窗口准入）

- **范围**：多分区只支持流送模式（`collision_window_radius_tiles > 0`）。“窗口”= 已安装 ∪ 已请求 ∪ 待装（`player.ex` 的 `window_domains` / `requested_window` / `window_pending`）。NPC 身体与其他无窗口实体（意图经 `movement/intent.ex:63-89` 进入、身体是热种子）在 S2–S4 多分区阶段**不运行**（只测试范围声明）；
  进入 Global system 前按玩家同一规则给 NPC 所有权半径（计入 S_want 与预取集），S4 前定。
- **跟随页（follower page）**：分片可持有**不归己**的页的只读版本。建立：读该页 owner 流的可见版本（PG 已发布页 + owner 日志后缀，与恢复同一读取 / 回放路径），并向 owner 登记跟随；之后 owner 每笔触及该页的提交在**写日志成功之后**（§2）把该笔日志条目经每跟随者一个的发送进程（CanonicalFeed 同一形态）按提交顺序发来，跟随者用恢复回放的同一函数应用。
  每个跟随源记游标与前驱链（§6.1）；页版本 = 最后改写该页的 seq（同页跨迁移单调，§6.2）。owner 退休保留事务前按 §4.5 第 0 条为跟随者钉保留下限；跟随断开或游标过期 → 丢弃该页并按上面的建立步骤重建。
  - **不是真值**（AGENTS SSOT）：跟随页不裁决、不模拟、不写回、不持久，进程重启即丢弃。它唯一的“升格”是迁移导入（§4.2）：导入的依据是 PG 中的持久事实（prepared 行与源日志 ≤ H），跟随状态只因“与从 PG 回放同值”而被直接采用（§4.3）；任何跟随页缺失时按建立步骤从 PG 重读，不得当空气或成功。
  - **不复用 Replica 进程**：Replica 只存载荷字节与投影、来源限定唯一 World（§2），不能支撑接管；跟随页与自有页同形态（同一解码可改形式），只是不在本分区 owner 行内。扇出复用 CanonicalFeed 的每订阅者发送进程形态。
  - **前提**：日志条目须能按页筛选——依赖 S1a（全局行拆分）与 M2b（身份定位）；现日志在实例表 / 附件归属变化时仍写整表（§2）。
- **跟随的三种用途**：(a) **预拷贝**：T1 / T2 计划后目标跟随全部成员，交接时由跟随转为拥有（§4.2）；(b) **边界带**（仅 D13 ①）：分区跟随“本分区玩家窗口（含 d_pre 预取）∖ 自有页”，窗口、碰撞、视野由它供数；(c) 迁移成员的旧跟随者在封口处改跟随新 owner（§4.5）。
- **边界带有界**（父稿“常驻随活跃区域有界”）：只跟随本分区玩家需要的页，**不跟随整条接缝**；上界 = 本分区玩家数 × 每窗口页数，与这些玩家的窗口本身同量级；无玩家处零跟随。离开预取范围后延迟退订（滞回参数 S2 定）。
  依据：SpatialOS 读兴趣可大于写权威（“interested in every object within a 100m radius of the entities it has authority over”，原文为举例句）；BigWorld ghost 是邻 cell 实体的只读副本，写只在 real。原句见“依据”。
- **窗口来源**：
  - **D13 ①（跟随页供窗口）**：CollisionStream 仍只向本分区分片请求窗口；分片以自有页（本流）与跟随页（他流，各自游标）组成快照，之后按各流顺序转发增量；Player 按“流 → 前驱”分别校验连续（取代单一 `+ 1`，§6.1）。窗口请求不等所有权。
    **须改协议**：客户端现只有一个会话 seq 域（§2 证据），两流交错会使自举 / 窗口 / fence / 移交的大小比较、`AppliedSeq` 变化检测、意图账 `<=` 判定、属性 `MinimumSeq` 对 `ConfirmedSeq` 比较出错。改法并入协议 42：内容守卫一律用**按页（tile）版本**（客户端已有 tile seq 守卫，且同页跨迁移单调）；
    会话时间线（窗口、fence、移交、碰撞事件）改用 Scene 分配的**会话观察序号**（CollisionStream 现有事件游标即此类序号）；变化检测与意图账改按“已应用事务集合 / 观察序号”。字节样本、golden 与 Voxim codec 同 §8 S5 规则，在 S3 验收前冻结。
  - **D13 ②（所有权覆盖窗口）**：r_own 覆盖窗口（§3.3），窗口永在本分区，协议 41 与客户端不改，不需要边界带。代价：岛按窗口而不是模拟半径扩张，合并更早、岛更大（热点更早触及 D4 单分片上限），T1 更多；合并迟到时表现为慢准备停步。
  - 两案相同处：玩家脚下与模拟半径内的页在正常路径都已归本分区（§3.3 所有权前置）；两案只差“窗口 ∖ 模拟闭包”这一圈由谁供数。
- **travel 盒**：保留现行“窗口盒向内收 1/4 tile”（`player.ex:2072-2087`）与慢准备停步——它约束的是窗口安装速度，单分区同样存在；v6 不再因所有权推迟窗口请求。零停顿验收以 K = 1 同路线为基线比较停步（§8）。
- **跨分区实体可见**：Scene AOI 30 / 34 m（§2）。分属两分区的玩家至少相距 2 · r_own + d_merge（r_own ≥ 一页 64 m），按提前合并规则不会出现在彼此 AOI 内（推断，S3 验证）；静态共面两区的邻 Scene 帧交换（`replication.ex:262-268`）保留。动态边界与 K ≥ 3 下 `authority.ex` 的共面半空间分工须在 S4 前改。

  传送不要求无缝，不计入零停顿验收，只测加载时长与各段分解。与现行 `player.ex:1430-1441` 的窗口内瞬达冲突：取消，单分区同样取消（D14 ①，用户 2026-10-26 已定）。客户端加载界面：Voxim 信标相关源文件中未找到加载状态，是否另有可复用的通用加载界面**未核实**（S2 前核实）。

## 4. 所有权交接合同（T1 冷页、T2 岛、TC 角色；v6 = 领导权转移）

### 4.1 行、锁与冲突边界

- PG 行：`voxel_partition(id, incarnation, state ∈ {running, stopped}, node)`；`voxel_base_slot(slot, partition)`；`voxel_owner(key, partition, version, migration)`（key = 页或 cid）；
  `voxel_owner_base(key, stream, seal_seq)`（基线链项 `(流, H)`，§4.4；v6 由 v5 的 `cut_limit` 改为封口序号）；`voxel_migration(...)`、`voxel_migration_member(migration, key)`。
- **物化**：写者对无覆盖行的页先在同一事务中 `SELECT … FOR SHARE` 其基础槽行，再 `INSERT INTO voxel_owner … VALUES (key, 槽的分区, 0, NULL) ON CONFLICT DO NOTHING`——值确定，任何插入者结果相同（FX2.3）。
- **权威写**（日志追加、页段写回、角色行写回、前缀发布）：同一 PG 事务内按规范键序 `SELECT … FOR SHARE` 本分区行（`incarnation = 我`、`state = running`）与所写每个 key 的 owner 行（`partition = 我`、`migration` 为空，或为以本分区为 dst 且 `imported_seq` 已落库、尚未 done 的迁移），不符即回滚并返回 `:stale_owner`。
- **所有权变更**（prepare 占用、commit 翻转、abort 释放、化身 bump、槽改派）：同样按规范键序 `SELECT … FOR UPDATE` 再更新。PostgreSQL：FOR SHARE “blocks other transactions from performing UPDATE, DELETE, SELECT FOR UPDATE or SELECT FOR NO KEY UPDATE on these rows”（explicit-locking，已核实）。
- **错误分类**（FX2.4）：`deadlock_detected`（40P01）、`serialization_failure`（40001）→ 重试整笔，未确认、未广播；只有加锁后校验失败（`:stale_owner`）才证明本进程是僵尸 → 停止进程。
- **第三种授权：收尾写回**（v6）：源对已翻转的成员写本流段行，只允许内容为 H 时状态、段行 `cut_seq` 标为 H；同一事务 `FOR SHARE` 迁移行并要求 `src = 我 ∧ src_incarnation = 我 ∧ state = 'committed' ∧ released_seq IS NULL`。目标经基线链 `(src, H)` 只看 src 流 `cut ≤ H` 的行（§4.4），源（含僵尸）写的任何更高版本永不可见。
- 正常运行中旧写者不会撞拒绝：成员自 prepared 起由占用列封住（`migration = m`，源自己也写不进），翻转只由目标在 prepared 之后执行；源对 H 之后触及成员的请求排队转发（§4.5）。拒绝只拦僵尸。成本（1 + k 个行锁读）S2 实测。仓内参照 `data_service/lib/data_service/body_store.ex:45-46`。

### 4.2 迁移状态机（v6：领导权转移；AX3.3、A3-B1、A4-N1 的守卫保留）

迁移行 `voxel_migration(id, kind, src, src_incarnation, dst, dst_incarnation, state ∈ {planned, prepared, committed, done, aborted}, seal_seq H, frozen_at F0, imported_seq, open_at F1, released_seq, unfrozen_seq, stock_j)`（v5 的 `base_cut B` 删除）。
**决定点仍唯一**：prepared 之后，目标的翻转事务与控制面的中止事务都先 `FOR UPDATE` 迁移行并要求 `state = 'prepared'`，先到者定局。v6 中翻转与导入同一事务，所以 committed 即已导入；`released_seq` 落库时置 done 并清本迁移占用。

| 转移 | 执行者 | 同一 PG 事务内的守卫与动作 |
|---|---|---|
| → planned | 控制面 | 插迁移行（id 幂等）与成员；成员 = W / 岛的绑定组闭包（T2 另含岛外圈）；通知目标开始跟随全部成员（§3.6 预拷贝） |
| planned → prepared（停写） | 源 | 前置（本地、不访问 PG）：目标已报告“跟随全部成员、游标落后 ≤ 一回合”；源在下一个合法提交边界停止接纳触及成员的意图与步进，H = 该边界的 `state.seq`、F0 = 当时时刻。事务（就是该回合源流的一笔提交，与每笔同步写日志同类，**不等切点**）：按 §4.1 物化成员 owner 行；源分区行 `incarnation = src_incarnation ∧ running`；`UPDATE voxel_owner SET migration = m WHERE key ∈ 成员 AND partition = src AND migration IS NULL` 且受影响行数 = 成员数（排除同页重叠迁移）；被迁流级实体打“冻结于 m”标记（随其持久行）；记 H、F0、`stock_j`；`WHERE id = m AND state = 'planned'`。成功后同一回合发封口（§4.5）；失败 → 回滚、解除内存停写、读迁移行 |
| planned → prepared（代为停写，源已 stopped） | 控制面 | 源 `state = stopped` 且化身已 bump、`prefix(src) ≥ 源流最后一笔`、满足停止前置条件（§4.7）；H = 源流最后一笔；成员物化与占用同上；`released_seq = 0`（无内存冻结表示、全部已发布，释放为空）。之后与常规迁移同路径由目标翻转 |
| prepared → committed（翻转 + 导入） | 目标 | 前置（本地）：已**消费**到源封口 H 且该源前驱链连续（跟随状态即成员在 H 的状态）；若跟随断开、源在发封口前崩溃或目标刚重启，改经基线链 `(src, H)` 从 PG 重装成员（H 已记在迁移行）。事务：`FOR UPDATE` 迁移行要求 `state = 'prepared'`；目标分区行 `incarnation = dst_incarnation ∧ running`；两端已应用目录摘要行相等（源已停止时取其停止时的摘要）；成员 `partition = src AND migration = m` 行数 = 成员数；翻转 `partition = dst, version + 1`（占用保持至 done）；写基线链 `(src, H)` ∪ 源对成员尚未截断的继承链；本流导入提交 I_m（§4.3）；`imported_seq = I_m, open_at = F1, state = CASE WHEN released_seq = 0 THEN 'done' ELSE 'committed' END`（done 时同事务清本迁移占用）。**不校验源存活**：prepared 本身就是“源自 H 起写不进成员”的持久事实（§4.1）。提交后同一回合开放成员的意图与步进，并通知源 |
| committed：记释放 | 源 | 源发布首个覆盖 H 的切点，且该切点含成员中“自上次写回后脏”的页的收尾写回（§4.1 第三种授权，cut 标 H）；发布后一笔释放提交 R_m：删除“冻结于 m”的表示与转发指针（§4.5），`released_seq = R_m, state = 'done'`，同事务 `UPDATE voxel_owner SET migration = NULL WHERE migration = m`；`WHERE id = m AND state = 'committed' AND released_seq IS NULL` |
| planned / prepared → aborted | 控制面 | **事故路径**：目标分区在 T_abort 内未运行或报告不可导入（T_abort S3 定参）。`FOR UPDATE` 迁移行要求 planned / prepared；`UPDATE voxel_owner SET migration = NULL WHERE migration = m`——只清本迁移的占用 |
| aborted：记解冻 | 源（曾 prepared 时） | 解冻提交 U_m（§4.3）与 `UPDATE … SET unfrozen_seq = U_m WHERE id = m AND state = 'aborted' AND unfrozen_seq IS NULL`；随后在本地按序执行排队请求（§4.5） |
| 源化身 bump（故障转移） | 控制面 | 该源 **planned** 全部置 aborted、`migration = NULL WHERE migration IN (这些 id)`、`unfrozen_seq = 0`（停写只在旧化身内存）；**prepared 不中止**：停写已持久，目标照常翻转；新化身恢复时把占用为 m 的成员作冻结装入，committed 的执行收尾写回与释放、aborted 的执行解冻 |
| 目标化身 bump | 控制面 | 不中止；目标新化身恢复时扫描 `dst = 我` 的 prepared，经基线链从 PG 重装成员后翻转（跟随状态随旧化身丢失，改走 PG，较慢）；目标在 T_abort 内未运行才中止 |

- **再次迁移门槛（A4-N1，保留）**：成员占用只在 done 时清，再迁要求 `migration IS NULL`——前一迁移的释放完成前成员不能再迁。源崩溃时由新化身做释放，门槛不会永久卡住；释放被拖延只延迟“再迁”，不影响目标使用成员。
- **源不自行解冻**；结果不明一律读迁移行，条件更新受影响 0 行即重读。恢复扫描：源 → 自己为 src 的 prepared（保持冻结；旧化身的排队请求已随之丢失）、committed 且 `released_seq` 空（做收尾写回与释放）、aborted 且 `unfrozen_seq` 空（做解冻）；目标 → 自己为 dst 的 prepared（重装后翻转）；控制面 → planned 超时中止、prepared 超 T_abort 中止。
- **planned 期间**的停写只在内存，源崩溃即消失，无不可逆效果。
- **不可写窗口 [F0, F1]** = 封口到达目标 + 目标消费剩余（停写前置保证 ≤ 一回合积压）+ 一笔目标 PG 事务（k 个 owner 行 + 迁移行 + 导入日志）+ 至目标下一回合。不含切点、不含控制面往返。目标 < 一回合，S3 实测，稿内不承诺数值。期间成员请求排队、不拒绝（§4.5）。
  对照：Clark 等的 stop-and-copy 停机（Quake 3 服务器 60 ms）对应这一段；PingCAP 记录“不涉及快照”的 TransferLeader 毫秒级完成、涉及快照的加副本需数十秒——v6 把数据搬运全部放在停写之前的跟随阶段。
- **预拷贝的开始**：T1 在页进入预取集时（§3.3）；T2 在两岛间距 < d_merge 时。停写前置“跟随落后 ≤ 一回合”保证不可写窗口内不追大积压；跟随追不上（源写入速率持续高于跟随回放）则不停写、继续跟随并计 `merge_late` 风险，S3 测量。
- **与 Raft 的差异（依据核实结果）**：Ongaro §3.10 的顺序是“旧 leader 先停止接受新请求，再把目标日志补齐，再发 TimeoutNow”；v6 在停写前先跟随（Raft 的 follower 本就持续复制，等价），停写后只补 ≤ 一回合。Raft 原文未规定转移期间请求如何处理（raft-rs 实现为丢弃提案），v6 取排队转发（§4.5）。

### 4.3 时点与提交（v6：H 与 [F0, F1]；AX3.4、AX3.7）

- **两个时点**：封口序号 H（停写回合的 `state.seq`，同时用于订阅封口、续订与存储基线）与不可写区间 [F0, F1]（F1 = 目标实际开放步进的时刻）。v5 的基线切点 B 删除：每笔提交在广播前已同步写入本流日志（§2），H 时成员的全部历史已持久，基线直接引 H（§4.4）。
- **导入提交 I_m**（目标流一笔真实事务，与翻转同一 PG 事务）：取号 `I_m > max(H, 成员最后 seq)`（§6.2）；成员状态取自跟随（已消费到 H）或基线链重装，二者同值（跟随与恢复走同一回放）；加入流级实体；成员页全部标脏（供链截断，§4.4）。
  **不平移在途过程时间锚点**：成员在 [F0, F1] 内未被任何流推进，目标首拍按实际经过时间推进，等价于源少走、目标多走一段 < 一回合的步长，与常规拍间抖动同量级；成员始终在模拟集内，不是 Q1 意义的“补算冻结期”。提交后同一回合开放意图与步进；`state.seq` 前进，按现有规则开切点、发布。
- **释放提交 R_m**（源流）：在首个覆盖 H 且含成员收尾写回的切点发布后执行；**只移除带迁移标记 m 的冻结表示**（成员页、角色与被迁流级实体，A4-N1 作用域规则不变）与转发指针；加上 §4.2 的再迁门槛，R_m 不可能触及之后再迁入的同键状态。源故障转移后，新化身从 PG 装入时把占用为 m 的成员作冻结装入，并执行收尾写回与 R_m。
- **解冻提交 U_m**（aborted 后，源流，事故路径）：时间锚点后移 `解冻时刻 − F0`（此时不可写区间可能远超一回合，按 Q1 不补算），随 U_m 持久、只做一次；恢复成员的意图接纳与步进，并按序执行排队请求。
- **存量记账**：迁移行的 `stock_j`（停写时源测；代为停写时由目标在导入提交中测并写入）。全局审计 = 各流已发布账 + `done` 迁移的 `stock_j` 进出对消。
- **恰好一次**：每笔提交与其状态转移同库同事务；重复请求读迁移行后返回同一 seq。
- **状态等价口径**：交接后的成员状态 = 从 PG 重启恢复得到的状态（与 M2a 重启等价判定器同一口径）。不持久的瞬态（待施放前摇等）与重启时一样不随迁；是否随导入携带列 §10。

### 4.4 持久化：流、基线链、可见版本、GC（v6 改基线）

- 流 = 一个分区的日志流；日志、页段、角色行、流级行都带流 id；前缀表主键 `(cv, 流 id)`；残留清理只删本流 `cut_seq > prefix(本流)`（现 `page_store.ex:35-42` 按 cv，须改）。
- **基线链（v6）**：链项为 `(流 Q, H_Q)`，含义“Q 流中 seq ≤ H_Q 的已持久内容”。翻转时目标得到 `(src, H)` 加上源对成员尚未截断的继承链。页段是 (段, 子块) 多行，成员页 p 的**可见版本按段取 max**：
  max{ 本流 `cut ≤ prefix` 的行 ∪ 链中每项 `(Q, H_Q)` 下 Q 流 `cut ≤ min(H_Q, prefix(Q))` 的行 }，若所得版本 < H_Q，再按序叠加 Q 流日志中该页 seq ∈ (该版本, H_Q] 的条目。即**恢复链 = 源已发布页 + 源日志 ≤ H（仅成员）+ 目标日志**。只引用已持久内容，他流未发布残留与 > H_Q 的行永不可见；跨迁移同页 seq 单调（§6.2）保证 max 正确。
- **收尾写回与源日志保留下限**：源发布的首个覆盖 H 的切点必须包含成员在 H 时的全部脏页（段行 cut 标 H，§4.1 第三种授权；若停写前已开的切点恰为 cut = H，它已按 owner 身份写过这些页，自然满足）。成员的 H 时内容与 `prefix(src) ≥ H` 在同一发布中进入页表；渐进删日志（`data_service/lib/data_service/voxel/page_store.ex:153` 只删 `seq ≤ 已发布前缀`）因此不会在收尾写回之前删到成员 ≤ H 的条目——下限由“收尾写回与前缀推进同一发布”自动满足，不另设持久钉。
  源在收尾写回前崩溃：前缀未越过 H、日志未删，新化身重做。代价：成员的源日志保留从“到下一切点”变为“到下一个覆盖 H 且含收尾写回的切点”，恢复链在此期间多一段源日志回放（§8 测量）。
- **链的截断**：导入提交把成员页全部标脏；某页在本流写回并发布后，删除该页的链（按页、随常规限速写回摊开，FX§3）。再导出时若链未截断，原样传递。
- **I4**：源对某页无任何可见版本时，基线记显式 `never_edited`；“新 owner 下无行”不推出从未编辑。
- **三种授权**（AX3.3；v6 增收尾写回）：权威写按 §4.1；收尾写回按 §4.1 第三种；**退休本流历史**（删本流 ≤ 前缀的日志、自有页低于可见版本的段行、已迁出页且**不被任何基线链引用**的段行——含收尾写回所写标 H 的行）在同一事务里对相应 owner 行取 `FOR SHARE` 并检查链引用，与翻转写链互斥。
- **一致读取**：分片先登记新化身（bump）再在一个 REPEATABLE READ 事务里读本分区 owner 行、基线链、链所引他流的页与日志区间、本流行、前缀与后缀（FX2.8）。多分区组合根只支持 PG 后端。

### 4.5 跨源订阅屏障与请求转发（AX3.5；v6 加转发）

1. **封口**：源在停写回合（H 已提交、H 之后的号未产生），对每个将迁走的订阅者——窗口订阅者与成员页的跟随者——经其发送进程发 `{:handover, m, H}`；窗口订阅者随后退订，跟随者对成员页改跟随目标。同源到同目标有序（Erlang “if an entity sends multiple signals to the same destination entity, the order is preserved”，已核实），封口恰在 H 与其后继之间。
2. **消费边界**：CollisionStream 把封口作为普通事件进入自己的 FIFO（与 delta 同序、同 pending 保留）；Scene / Player **消费到**该事件时才停止接受源对成员的 delta、等待目标首笔。前驱不因控制消息提前改写。
0. **续订保留下限**（v5 统一，A4-N2）：每个未收口的交接在其续订基点处钉一个保留下限——源钉在 H（从封口起到被封订阅者回接或超时），目标钉在 I_m（从导入起到被迁订阅者接上或超时）；跟随者同样受此下限保护。下限同时约束内存保留事务的退休（`world/page_cut.ex:259`）与日志渐进删除（`page_store.ex:153`），只在内存、随超时放开；放开后到达的续订一律显式 `cursor_expired` → 调用方走既有 `canonical_snapshot_and_subscribe` 显式整窗重取并计数，不静默跳到当前 seq。
3. **目标续订**：I_m 提交后即开放写入；`subscribe_handover(m, H)` 校验迁移 id 与 H，回复“源封口 = H，首笔 = I_m”，从 I_m 起按序补发全部保留事务（含开放写入之后的已确认事务），**不以目标当前 seq 作续订点**；超时后按第 0 条处理。
   正确性：H 之后到 I_m 之前成员页未被任何流写过（源停写、目标未导入）。D13 ② 下被迁订阅者的窗口 ⊆ 被迁岛 ⊆ 成员，“消费到 H + 从 I_m 起补发”无遗漏（v5 论证不变）；D13 ① 下组合窗口的分片按页记来源流，成员页在 H 处由源流封口、自 I_m 起改由目标流供数，非成员页的来源流不受影响。
4. **前驱**：每笔提交在日志中记录本流前驱 seq；Player 按流校验，消费封口后对成员期望“首笔 = I_m”，之后按 I_m 所在流的前驱链校验。
5. **请求转发（v6，取代 `{:error, :migrating}`）**：
   - **排队**：源在 [H, 决定] 收到触及成员的写请求（编辑、维护、意图、交互）按到达顺序进本迁移队列，不回复、不拒绝。**窗口请求不排队**：成员自 H 冻结，源立即以 H 时状态回快照，续订按第 3 条。
   - **转发**：committed 后源按队列顺序转发给目标，每条携带原调用方的回复地址（`GenServer.call` 的 `from`），目标执行后直接 `GenServer.reply/2`，回包不经源；结果 seq 属目标流且 > H。翻转后源对成员保留内存**转发指针**，按陈旧路由误投的请求同样转发，直到 done 且新分区表版本已发布到全部路由方。
     依据：BigWorld “Each ghost knows its real cell, so that it can forward messages to its real version to be processed.”；对照：CockroachDB 非 leaseholder 返回带新 leaseholder 指针的错误、raft-rs 转移中丢弃提案——业界也有拒绝 + 重定向的做法，v6 按用户要求取转发。
   - **中止**：源在 U_m 之后按队列顺序本地执行。
   - **顺序**：同一请求方到同一源的请求按 Erlang 同源保序进队、按序转发；请求方只在收到携带新分区表版本的回包后改投目标，且改投前等待其发往源的在途请求全部回复——同一请求方的请求在目标上仍按发送顺序执行。客户端只要求增量与结果 seq 单调（§2），转发结果来自目标流，满足。
   - **幂等**：队列在决定后只清空一次，每条只转发一次；带回执键的维护请求按 PG 唯一键幂等（§3.5）；玩家编辑重投的去重沿用现行意图合同（其服务端去重键本稿**未核实**，S3 前核实）。源在转发前崩溃 → 队列随进程丢失 → 请求方按现行超时处理（事故路径，§4.8）。
   - **与僵尸拒绝（`:stale_owner`）**：转发是活进程之间的路由，`:stale_owner` 是 PG 写时的安全底线，二者互不替代。目标从不因“来自转发”放宽 §4.1 检查；未得知翻转的僵尸源若自行执行请求，写被拒、进程自停，其队列随之丢失（事故路径）。
6. **失败（事故路径）**：源在封口前崩溃 → 现行源 DOWN 即停（`collision_stream.ex:73-75`）→ 会话显式失败重连；目标仍可经基线链翻转（§4.2）。中止 → 订阅者对源以 `subscribe_handover(m, H)` 自续（源保留下限钉在 H），从 H 的后继起按流前驱链补发（含解冻提交 U_m），前驱链从 H 连续接上；源重启或下限已放开 → 显式 `cursor_expired` → 整窗重取。
7. 多分区阶段不运行 Replica、不支持非流送 Scene（其 `baseline_transaction_seq` 共同基线守卫 `collision_updates.ex:171-172` 不适用跨源；流送路径该字段为 nil）。传送不走本屏障，走加载（§3.6）。

### 4.6 角色交接与失败收敛（AX5.1、AX3.7）

**单独迁角色（TC）**只出现在传送加载、换分区登录与退役中，均不在零停顿目标内。顺序：Scene seal → 取消施法、等 `body_detach`（旧热量先收口）→ 身体最后保存（`BodyStore.save`，旧 `session_epoch`）→ TC（领导权转移：目标跟随该 cid 行，源在提交边界停写 → prepared → 目标翻转导入）→
`WorldServer.Session.commit_transfer` → 目标 `BodyStore.claim`、Player 激活。**随 T2 迁移的玩家**（提前合并）：角色行是 T2 成员，Scene 按 M4a 移交；客户端移交只换身份、预测不停（§2）；服务端 `transfer_cut → transfer_resumed` 区间计入不可写窗口测量；合并时是否仍须取消施法（v5 的 TC 顺序会打断施法，属可见停顿）列 §10。
**收敛规则**：TC 未 committed 前任何失败 → 角色与账留源，Session 移交中止（现 M4a 准备失败语义）；TC committed 之后任何失败（Gate 断开、Session 提交失败、claim 失败）→ 会话关闭，玩家重连时**在角色行当前 owner 分区登录**，无需再迁移。身体的 `session_epoch` 与分区化身是两个合同。
**换分区登录**：角色行仍在下线时的分区 → TC；该分区运行中则正常迁移；已停止 → 控制面代为停写（§4.7）；故障中 → 待故障转移完成，期间登录显式失败（D2）。

### 4.7 分区生命周期（FX2.5、FX2.8）

- **启动**：控制面 bump 化身并置 `running`、指定节点；分片先登记再读快照（§4.4）。
- **停止前置条件**：无已接纳模拟页（岛已迁出或冻结过程已按 Q1 冻结且不属任何岛）、流级瞬态集（在飞投射物、拟态、待交付）为空或已随 T2 迁出、无未决迁移、无跟随者（跟随者已改跟随或退订）。
- **停止 / 退役**：满足前置条件 → 分片停止接纳 → 发布全部（前缀 ≥ 最后一笔）→ 控制面置 `stopped` 并 bump 化身（封住僵尸）。退役 = 对其全部覆盖行（页与离线 cid）做迁移 + 把其基础槽改派给继任分区（槽行 `UPDATE`，与写者对槽行的 `FOR SHARE` 冲突）。
- **代为停写**（v6，取代代为翻转）：对 `stopped` 分区由控制面直接置 prepared（H = 源流最后一笔、释放为空，§4.2），之后与常规迁移同路径由目标翻转；离线角色的换分区登录、退役时的覆盖行迁移都走这条。
- **故障转移**：bump 化身（只中止其 planned，§4.2）→ 在新节点启动。

### 4.8 故障（事故路径）

下列情形都是**事故路径**：显式降级、记结构化日志、计入 §8 测量，但不是正常玩法规则；正常路径不含其中任何“等待 / 拒绝 / 冻结”。

| 故障 | 行为 |
|---|---|
| 分片崩溃 | 本节点重启、按 §4.4 恢复；期间该分区意图显式失败、其 Scene 停 Tick；其他分区不受影响，跟随它的分区对其页显式过期、待其恢复后重建跟随 |
| 节点崩溃 | 故障转移；会话断开重连 |
| 僵尸（与控制面失联、仍连 PG） | 下一笔权威写被拒并自停；**此前它仍可能向本节点读者供旧快照**，读不受化身保护；会话随故障转移关闭 |
| 控制面停机 | 本分区内闭合的编辑与模拟照常；已 prepared 的迁移由目标照常翻转（不需控制面）；新的 T1 / T2 / TC 计划、登录、移交、目录发布、保护区认领显式失败或停在原状态；所有权前置与提前合并停止 → D13 ① 下玩家移动照常、接缝按 Q1 墙，D13 ② 下按慢准备停步；计 `prefetch_late` / `merge_late` |
| PG 不可用 | 每笔提交同步写日志即失败（现行）：该分区意图显式失败、模拟不推进；迁移停在原状态 |
| PG 死锁 / 串行化失败 | 整笔重试，不算僵尸（40P01 / 40001） |
| 源在 prepared 后崩溃 | 目标照常翻转（必要时经基线链重装）；排队请求丢失，请求方超时 |
| 目标在翻转前崩溃 | 目标新化身经基线链重装后翻转；T_abort 内未运行则中止、源解冻（锚点后移，在途过程可见暂停） |
| 迁移超出包络（预拷贝 / 交接慢于 d_pre、d_merge 的设定） | `prefetch_late` / `merge_late`：表现同“控制面停机”中的降级 |
| 迁移任一步失败 | 按 §4.2 唯一持久决定收敛 |

### 4.10 保护区认领的两阶段提交（D7-A″；A3-B3、A4-N3；v6 去掉迁移暂缓）

本设计唯一的跨分区原子提交，只在 D7 选 A″ 时存在。用简单拓扑互斥保证参与者集合有效，不建通用事务框架。
- **登记**（控制面，PG）：`protection_region(id, rect, holder, state ∈ {pending, committed, aborted, released}, version)`（version 每次状态变化 +1）；`protection_participant(region, partition)`；`protection_vote(region, partition, vote)`。
- **发起**：控制面一事务——检查与全部 pending / committed 区域不重叠、每持有者数量；**参与者集合 = 此刻全部 running 分区**写入 participant；存在既未运行又未退役的分区 → 直接 aborted（显式“分区不可用”）；写 pending。
- **拓扑互斥（v6 缩小）**：pending 期间控制面只排队**分区启动 / 停止 / 退役**与**列内基础槽改派**（玩家不可见的控制面操作），直到该认领决定；**迁移照常进行**。于是参与者集合在 pending 期间覆盖全部可能拥有列内页的分区。故障转移不能被互斥，但阻挡与投票在同一持久提交里，新化身回放即继承。
- **投票**：参与者在合法提交边界做一笔本流提交，PG 事务内先 `SELECT … FOR SHARE` 认领行并要求 `state = pending`：复核本分区拥有的列内页有无他人占用（`world/claims.ex:84-93` 同一判据）；无 → 在这些页上记录**写入阻挡**并投 yes；有 → no。阻挡、投票行与该提交同一 PG 事务；认领已非 pending 时整笔回滚，迟到的投票不会在 aborted / released 后装上阻挡。阻挡不改 holder、不重建热域、不唤醒液体、不广播保护投影。
- **阻挡随页（v6）**：写入阻挡按页记在页数据上（矩形 ∩ 本分区页），随迁移成员一同停写、导入，与页同一持久化。
- **导入补验（v6，取代“列内迁移暂缓”）**：导入提交若有成员页落在某 pending 矩形内且**不带**该认领的阻挡（源尚未投票），而目标已投 yes，则在同一 PG 事务内 `FOR SHARE` 认领行（要求 pending），按 `world/claims.ex:84-93` 复核这些页：无他人占用 → 加阻挡；有 → 把目标的票改为 no。目标尚未投票时，其后的投票自然覆盖已导入的页；源已投 no 时决定必为 aborted。
  于是决定时每个列内页都在“其当前拥有者的投票或导入补验”中复核过并受阻挡，不需要冻结迁移；代价只是导入事务多一次 `FOR SHARE` 与占用复核。
- **挂起而非拒绝（v6）**：阻挡期间矩形内非持有者的写请求在该分区排队至认领决定：committed → 按保护拒绝（与“认领先于该编辑”的串行结果相同）；aborted → 按序执行。队列只在内存，分区崩溃即随之丢失（请求方超时，事故路径）。
- **决定点**：控制面一事务 `SELECT … FOR UPDATE` 认领行（与投票、导入补验的 FOR SHARE 互斥）——participant 全部 yes → committed；任一 no 或超时 → aborted。version +1。唯一持久决定。
- **生效（按版本幂等）**：各分区把“已应用保护版本”记在本流全局行；读到决定后在提交边界一笔提交：仅当该认领 version > 已应用值时应用——committed → 装入保护投影（今日 `commit_protection` 的全部效果，`world/claims.ex:98-110`）、撤阻挡、拒绝挂起请求；
  aborted → 撤阻挡、执行挂起请求。重复通知、重启回放都按版本跳过。物理只在决定之后变化，从不补偿撤销；各分区生效时刻不同，因分区间无物理耦合（§3.2），不产生跨分区不一致。
- **恢复**：分区重启从本流恢复阻挡与已应用版本，补做已决定未应用的；控制面重启把 pending 推到决定（超时 aborted）并解除拓扑互斥。认领请求的回复等到决定后返回（有超时）。
- **释放**：无需复核，控制面一事务置 released、version +1，各分区按版本在提交边界移除投影。

## 6. 序号与身份（AX3.6）

### 6.1 两个号源，各自合同

- **提交号 seq**：一笔事务一个。45 处 `seq + 1` 中，凡表示“本笔将取得的提交号”的（回执 seq、实例 birth、保护区 id、`tools.ex:495` 世代、`production.ex:48-51` 骰子种子）改读 `state.next_seq`；
  `log_projection.ex:39` `iterator_from(have_seq + 1)` 是游标下界，不改（FX§3）。
- **附件号 aid**：一笔零到多个（`prefabs.ex:463-470` 每组一个、`parcel.ex:107-110` 批量）。改为本流独立的 aid 号块，按需逐个取；不再用 `max(serial, seq) + 1` 与 seq 耦合（块分配后耦合会跨入他流号段）。
- **前驱链**：每笔提交在日志行记录本流前驱 seq；`collision_updates.ex:256`、`player.ex:1830` 改为校验前驱，保留漏消息检测。**积压**：`page_cut.ex:118` 改为本流已提交未发布的事务计数。
- **K = 1 等价口径**：seq 逐项相等（单块时号仍连续）；aid 数值会变，只验“唯一、引用一致、回执与实际提交一致”。客户端只按相等比较 aid（`VoxelDamageState.cpp:176-177`），不受影响。

### 6.2 号块：PG 计数行（K ≥ 2 启用）

- 每类号一行 `voxel_number(cv, kind, next)`；领块 = `UPDATE … SET next = next + n WHERE cv AND kind RETURNING next - n`，**提交后才使用**。并发领块在该行上串行：READ COMMITTED 下后到者“will wait for the first updating transaction to commit or roll back … attempt to apply its operation to the updated version of the row”
  （https://www.postgresql.org/docs/current/transaction-iso.html ，已核实），故各块不相交、按提交顺序递增。不用 sequence（CACHE > 1 时跨会话可乱序，AX3.6）。重启丢弃未用块尾，前驱链不受影响。
- 承诺：全局唯一、流内单调、同页 / 同角色跨迁移单调；**不承诺跨流实时有序**。
- **导入取号**（T1 / T2 / TC 都适用）：采纳 F 原规则——`max(state.seq, H, 成员最后 seq) + 1`（v6：封口序号 H 取代 v5 的基线切点 B）若仍在本流已领块内则用之，否则领新块（新块必大于此前全部已领块）。v2 以“可能落进他流块”拒绝该规则是误读（AX1.5）。
  Lamport IR2(b)：“sets Cj greater than or equal to its present value and greater than Tm”（CACM 21(7) 1978 p.560，已核实）。
- **首次启用**：计数起点 > max(现 seq、`attachment_serial`、全部已发 seq 派生身份)。
- 父稿“新格式不再把全局 seq 当跨区唯一键”在此修订为：保留 seq 派生身份、由块保证唯一。备选（D6）：每分区连号 + 命名空间身份（实例 id、世代进协议）。
