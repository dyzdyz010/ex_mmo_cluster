## 2. 分批暂存 + 请求移交的时序核对

读过的路径：`need/5` 冲突判定（`page_load.ex:110-124`）、`stage/4`（`:130-136`）、`commit/2`（`:139-151`）、`yield/3`（`:154-165`）、`finish/3` 撤销暂存（`:171-185`）、任务 `loop / stage / commit`（`:229-300`）、World 的 `page_*` 分派（`world.ex:795-825`）。

### 2.1 不丢消息、不死锁 — 成立
- 让出 = 把自己的条目并入对方任务后**退出**（`:238`、`:154-165`），`finish` 撤销自己的暂存（`:178`）；两个任务互相撞页时先撞的一方退出、另一方下一轮 `need` 已无冲突，不存在互等。
- 让出时对方已结束（`tasks[other]` 为 nil）：条目留在自己名下，自己随后正常退出 → `finish` 重放（`:162-163`，`world.ex:1560`）。对方已 `page_commit` 但 DOWN 未处理：条目并入对方，随其 DOWN 重放。两种时序都不丢。
- 模拟的 `:wake` 被让出后 `sim` 标志随接收任务结束才清（`:180` 看 `entries`），期间 `request` 一直回 `{:loading}`，正确。
- `need` 回令牌与 `stage` 之间别的任务抢先暂存同页：`stage` 丢掉该页（`:132`），本任务照常闭合其余页；该条目重放时再过闸、再撞页、再让出（`:242`、`:132`）。只多一次 PG 读，不丢。
- 任务卡在 PG：`:infinity` 调用，但 Postgrex 自带查询超时会让任务异常退出 → 条目回错 / 撤销暂存。与修补前同一类，只是现在被撞页的条目一起等。

### 2.2 不见半棵树 — 成立（闸只看 `resident`，暂存页不驻留）
`missing_keys` / 洪泛冷页检查 / `tree_complete?` 都按 `resident?`（`page_load.ex:70`、`:97`；`liquids.ex:260`；`pages.ex:98`），暂存中的页一律视为未驻留；`commit_missing` 对暂存页上 home 的每棵树核对根覆盖页（`pages.ex:638-640`），缺则 `{:more}` 继续读（`page_load.ex:297`）。`:392-423` 用例确实走了“撞上暂存页 → 让出 → 对方闭合后重放”这条路。

### 2.3 【中】重放第二次起不再等身份：让出后由不含该树的任务重放，可按未驻留的暂存数据裁决（推断）
`gate` 在 `attempt > 0` 时把 ids 清空（`page_load.ex:64`），原意是“查无此身份的 id 不无限挂起”；但让出后的条目用的是**接收任务**的 `attempt + 1`（`world.ex:1560`、`:1615`），而接收任务只闭合自己暂存页上 home 的树（`pages.ex:638`），不保证让出方正在定位的树闭合。时序：
1. 根 X home 在 H、覆盖 {H, Q}。窗口任务 D 正在暂存 Q（不含 H）。
2. `instance_cells(X)`（attempt 0）起任务 A：定位 → H → 读 H、暂存 H（X 记录进内存）→ 闭包要 Q → Q 被 D 暂存 → 让出给 D，A 退出，`finish` 撤销 H 的暂存（数据仍在内存，H 不驻留）。
3. D 正常闭合（Q 上没有 home 的树，不会补 H）→ 条目以 attempt 1 重放：ids 清空，`Closure.tree(X)` 因 `tree_complete?` 为假只给 `{[], [X]}`（`closure.ex:175`）→ 页为空 → **放行**。
4. `instance_cells` 从未驻留的 H 数据作答；换成 `remove_prefab`，提交写到未驻留页 H 的单元，之后 H 被别的任务正式装入时 PG 旧行覆盖内存（`pages.ex:774-789` 合并），已拆的格复活。`posed` / `missing_pages` 的 `defer` 硬编码 attempt 1（`page_load.ex:74`），GM `move_instance` 经它重放时同样跳过 ids。
最小修法：attempt > 0 只跳过**内存里没有记录**的 id（真正查无此身份），内存里有记录但 `tree_complete?` 为假的仍进 ids 继续定位补根；一行改动，补一个“A 定位中让出给只含覆盖页的 D，重放后仍等 H”的反例（现有夹具 `GateRead.hold` 可做）。

### 2.4 【中】粗层祖页随首批暂存长期占住：L5 页覆盖 2 km 立方，同范围所有带祖页的请求都排在一次整树装页之后（性能 / 公平，非正确性）
首批 `page_stage` 把本轮全部页键记为暂存（`page_load.ex:276`），含窗口预备 `with_ancestors` 带来的 L1–L5 页；它们一直占到整棵树闭合（§7 实测单次 6.8–11.6 s）。期间同一 L5 立方内任何 `prepare` / 编辑 / `serve_item`（L≥1）/ 热液步前检查（`with_ancestors`）都撞页让出，等它结束后再重放、再各自起任务；§7 的“首次装页中位 1.16 s”就是这个排队。不会死锁（2.1），也不会饿死（每跳都有页变驻留），但 8 个窗口在如园会被串成链，且让出方已读的 L0 页被撤销后要重读。
建议（后续，不阻塞）：粗层页与不带身份 / 引用的 L0 页闭包是平凡的，可在每批暂存时直接标驻留，只让带 identity / refined / macro_owners / attachments 的 L0 页等树闭合；这样祖页不再被整树装页占住。

### 2.5 轻项
- 暂存被撤销后数据留在内存但页不驻留（`finish` 只清 `pending`），重装幂等；M2b 不淘汰，只是常驻多一点。
- 每批 `page_stage` 都经 `call/3` 的热域写回子句（`world.ex:791-793`），r116 468 批即 468 次 flush；成本项。
- `stage` 后 `Thermal.touch(loaded)` 可能按暂存页上的热行唤醒热提交，步前检查再因该页未驻留而暂停 / 让出；行为正确，只是多一次来回。
