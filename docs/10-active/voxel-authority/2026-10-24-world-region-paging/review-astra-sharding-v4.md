## 2. 本轮仍需修正的严重接缝

### N1【严重】导入后立即清占用，允许旧释放尚未完成时再次迁移；迟到释放没有版本作用域

证据：S:191 在导入完成时就清成员 `migration`，不等 `released_seq`；S:206 的 R_m 直接“从源状态移除成员页／角色／流级实体”，没有限定旧 owner version。S:197 又承诺任意先后均收敛。
推断：M1 把 p 从 A 迁到 B，B 已导入但 A 的释放通知迟到；占用已清，M2 可把 p 从 B 再迁回 A。A 导入新版本后再执行 R_M1，会按同一页键删掉新取得的 p。两次迁移的决定、成员数与化身守卫都可以通过；“R_M1 只执行一次”不能防止它清错版本。网络消息丢失后重接、延迟恢复可产生这一顺序，不能依赖未写明的通知顺序排除。
最小修改：要么前一迁移完成到 done 前禁止成员再次迁移，要么把释放严格绑定于旧化身／旧 owner version 的冻结表示，证明不会触及后来导入的状态。页、cid、流级实体使用同一明确边界。
同组补齐**代为翻转的共同守卫**：S:188 只列 stopped 源和空释放，没有列正常翻转 S:189 的目标 running、两端目录摘要一致、owner version 递增。推断：停止于目录 V1 的页可被直接交给 V2 目标。该分支只能豁免活源 prepare／实际释放，不能豁免目标与版本兼容；应明确复用共同守卫。

### N2【严重】目标续订钉住 I_m，但 abort 回源没有相应的历史保留或过期出口

证据：S:228—229 只保护目标 I_m；S:232 要求 abort 后“源从 H 之后起补发”。当前 `VR/world/page_cut.ex:259` 退休 `seq ≤ 已发布切点` 的内存条目，`DS/voxel/page_store.ex:153` 删除同范围日志；`VR/world.ex:1353—1354` 对过期游标明确返回 `:cursor_expired`。
推断：H=100 封口，B=120 发布并退休旧历史，随后迁移 aborted。源无法兑现从 H 补全前驱链的承诺；即使 101–120 对成员都是空投影，后续 U_m 的流前驱仍不能直接接到 100。H/B 分开后这是一条正常失败路径，不只发生在源崩溃时。
最小修改：明确源在决定／回接期间保留 H 后缀，或对 abort 回接同样定义 `cursor_expired` 后的显式快照／会话失败出口。不要静默跳到当前 seq，也不要用成员几何未变代替流顺序证明。

### N3【严重】D7-A 的 yes 尚未绑定参与者集合与持续有效的阻挡，拓扑变化可使投票失效

证据：S:269 的票仅含 `(region, partition, vote, seq)`；S:270 广播“全部 running 分区”；S:273 依据“全部 yes”决定。§4.7 允许启动、停止、退役和页迁移，但没有与 pending 认领联动。占用检查是实际内容检查：`VR/world/claims.ex:84—92` 扫描他人放置者／实例，不能由旧票永久替代。
推断：A、B 已投 yes 并安装矩形阻挡；在决定前启动 C 并把相关页迁入 C。C 不在原广播集合，其流中没有投票／阻挡，允许他人新建；控制面仍按 A、B 的 yes 提交认领，便接受了已经不满足的“无他人占用”。若“全部”按当前拓扑解释，则 C 从未收到 prepare，合同又没有补投票／重新准备的推进规则。
最小修改：写清参与者集合／有效化身、阻挡覆盖与决定的共同边界；pending 期间的新分区、重启、页接管须先继承有效阻挡或使准备失效并重新投票。投票须条件绑定仍为 pending 的认领，迟到 prepare 不能在 aborted／released 后重新安装阻挡；决定与应用按版本幂等收口。可以采用简单拓扑互斥，不必新增通用事务框架。
