## 3. v3 新机制：新发现

**【中】3.1 prepare 的占用更新假定成员 owner 行已存在。** 稿:163 `UPDATE voxel_owner SET migration = m WHERE key ∈ 成员 …` 要求“受影响行数 = 成员数”，但 §4.1 只让**写者**在首次持久写时物化 owner 行；T1 划走从未写过的冷页（最常见的“岛向冷地生长”）时无行可占，prepare 必然失败。
补一句：prepare 事务先对成员按 §4.1 同一规则物化（`FOR SHARE` 槽行 + `INSERT … ON CONFLICT DO NOTHING`），再做条件更新。

**【轻】3.2 代为翻转与守卫表不一致。** §4.7 “`stopped` 且前缀覆盖全部日志的分区可不经 prepare 直接 committed”，而 §4.2 committed 守卫要求 `src.state = running` 且成员 `migration = m`。需为该路径单列转移：守卫 = `state = stopped ∧ prefix(src) ≥ 本流最后 seq ∧ 成员 migration IS NULL`（同样先物化、再占用、再翻转，一个事务）。

**【中】3.3 窗口准入只约束带窗口的玩家；无窗口实体（NPC 身体、非流送路径）没有准入规则。** `SS/movement/intent.ex:63-89` 的意图来源含 NPC；NPC 身体是热种子（`thermal.ex:379-380`）且随 Scene 移动，可走进他分区页。稿:200 只写“不支持非流送 Scene”。
应明确：多分区阶段 NPC 不参与（Test-only 范围），或 NPC 按同一准入规则受当前所在页所属分区约束。不阻断批准。

**【中】3.4 D11 ① 的前提本轮核实：现行目录成立，但不稳固。** 当前发布目录（`Content/Voxel/Properties/Playable/Published/e63744e2….json`，89 种）6 种导电材料（id 24、40、41、42、43、45）无 worldgen 标记；
worldgen v2 设计（`docs/10-active/voxel-authority/2026-08-24-worldgen-v2-3d-density-materialization.md:49-50`）原句“biome、ore distribution 分成独立生成层……矿脉均后置”——现阶段无天然矿脉。
但旧版目录（24 种）里同一 id 24 名为 **CopperOre**（同电导率 5.8e7），说明天然铜矿是预期内容；矿脉层落地后潜在连通图将沿矿脉无界。建议 D11 ① 加限定“潜在图只计玩家放置 / 加工的导体，天然矿脉材料不计”，并把这条写进决策表供用户一并定。

**【中】3.5 两阶段激活的“阶段二等待全部订阅者接上”可以去掉。** 稿:196-197 既规定迟到订阅“从 I_m 起补发全部保留事务（含阶段二之后的已确认事务）”，则阶段二等待只影响保留量而非正确性；等待却让已导入岛的物理与编辑再停一段（超时取值 §10 自认未定）。
推断：改为“激活即开放写入；从 I_m 起保留事务直到期望订阅者全部接上或超时；超时前退休即 `cursor_expired` → 显式整窗重取”，与 m2a R6 同一语义，少一个超时参数。

**【轻】3.6 S2 远景“他分区页在 PG 的最新已发布版本”的成本未提。** 一个 L3 区域 = 512 个 L0 页，每页要查 owner 行 + 基线链 + 对应流前缀再取段；只在重取时发生，Test-only 可接受，S2 测量项宜加一行。

**【轻】3.7 其余新机制复核无新问题**：迁移占用列 + `version` 与权威写 `FOR SHARE` 的冲突边界自洽；基线链按段取 max 的前提（同页跨迁移单调）由 §6.2 导入取号保证；释放 / 导入提交只写流级行与成员页、与状态转移同事务，恰好一次成立；
计数行 `UPDATE … RETURNING` 领块在 READ COMMITTED 下串行（与本人所知 PostgreSQL 语义一致，本轮未打开该页）；aid 独立号源不再与 seq 耦合；`log_projection.ex:39` 不改的分类正确；
`VoxelLodWorld.cpp:1634-1637` 守卫只在 `OnlyRegion` 分支、`:1603` 实时路径传 nullptr、`VoxelIntentLedger.cpp:46` `ResultRef <= AppliedSeqAtSubmit` 三处事实已核，§7 精确入口描述正确。
