## 2. v2 是否正确吸收两份首轮的【严重】与必改项

**【轻】2.1 逐条对照 §0′：全部吸收，无遗漏。** F 的四项【严重】（F2.1 → §3.1 绑定组；F3.1 → §4.1；F3.2/5.1 → §4.3；F4.2 → §7）与 A 的十项【严重】（A1.2 → D7；A2.1 → §3.1；A2.2 → §3.3；A3.1 → §4.1；A3.2 → §4.2；A3.3 → §4.3；A3.5 → §4.8；A4.1 → §6.1；A4.2 → §4.4；A5.1 → §4.5）各有落点。
v2 对 F 的三处不采纳（x/z 页列、`max+1` 取号、claim 读源流后缀）理由都成立：`max+1` 可能落进他流已领块（稿:258）正确；读源流后缀破坏流隔离正确。

**吸收后新引入或吸收不完整的问题：**

**【中】2.2 在飞投射物 / 拟态改为“中心所在页的页数据”（稿:136）引入页级抖动与跨页搬记录。** 投射物 50 ms 一笔（父:54 `:projectile_tick`），飞行中每跨一页就要把记录从一页删、另一页建，两页都变脏；`VR/world/projectiles.ex:53-95` 的 `sample` 每步重算位置。
推断：在飞实体应是**流级数据**（随 T2 整体迁移，与热总账同轴），落地 / 停在边界后才归页。A2.4 要求的是“归属明确”，不是“必须归页”。

**【中】2.3 §4.1 的 owner 行“第一次被持久写或被迁移时物化”未说由谁、以何值物化。** `FOR SHARE` 要求行存在；T1 划走一个从未写过的冷页时无行可翻；僵尸分片若按自己的旧表版本 INSERT 行，会把自己写成 owner。
最小补法：物化只由控制面做，或写者用 `INSERT … ON CONFLICT DO NOTHING` 以**基础网格函数值**插入（确定性，任何插入者同值），再 `FOR SHARE` 读实际值校验；翻转对无行页先 INSERT 再 UPDATE。

**【中】2.4 §4.1 写者（多行 `FOR SHARE`）与翻转（多行 `UPDATE`）可互相死锁。** 推断：写者已共享锁 p1、再要 p2；翻转已排他 p2、再要 p1 → PG 死锁检测中止一方。冻结后正常写者不存在，但 T1 不冻结他页、作者 / GM 入口可随时写任何页。
需要：双方按页键规范序加锁，或翻转用单条 `UPDATE … WHERE page IN (…)`；且 `deadlock_detected` 不得走“`stale_owner` 即停止进程”（稿:169）那条路——它是可重试错误，不是僵尸证据。

**【中】2.5 分区生命周期缺失：T1 / TC 的“源”可能不在运行。** §5g “拆 / 合 = 起停分区对”、§4.5 “换分区登录走 TC，源不可用则登录显式失败”。推断：分区被合并退役后，其 owner 行（页、离线 cid）仍指向它 → 下线于该分区的角色永远无法登录；冷页 T1 也找不到源做 prepare。
必须写：**分区退役 = 把它拥有的全部 owner 行（含离线 cid）迁走后才停**；已干净发布且无运行化身的分区，控制面可免 prepare 直接翻转（源无未发布残留，`prefix(src) ≥ 最后写`）。

**【中】2.6 D3 漏列 T2 对被迁小岛玩家的可见代价。** §4.2 第 2 步：冻结期间该岛“停止接纳写这些页 / cid 的意图（`{:error, :migrating}`）”且“暂停该岛步进”；D3（稿:311）只写“接缝不授资格、停步”。被迁一侧玩家在整个 T2 期间不能挖放、物理静止——这是 R-merge 的主要可见代价，须进 D3 供用户决定。

**【中】2.7 §3.6 “走近收窄边界时预先发 T1”没有前置距离参数，而 T1 延迟下界 = 等热提交边界 + 一次切点。** `page_cut.ex:179-182` 在 `thermal_run` 期间只重试；M0 有活动时热回合数秒（父:450-454）。推断：前置距离（页数）× 步行速度 必须 > T1 p99 延迟，否则玩家频繁撞上停步墙。应作为 S2 测量项与可配参数写入 §3.6 / §8，不是阻断。

**【轻】2.8 §4.1 “僵尸收到 `stale_owner` 即停止进程”遇启动竞态会误杀健康分片。** 分片按 §4.3 一致读取后、向控制面登记化身前，若控制面已免 prepare 翻走某页，分片第一笔写即 `stale_owner`。补一句：先登记化身再读快照；有活化身的分区不免 prepare。

**【轻】2.9 绑定组初始化可能连锁。** 稿:99“跨基础网格的存量绑定组整体划给一侧”——绑定组之间可经共享页连成连通分量（如园 g2 “实例树与水互相咬合”，父:426），初始化须按绑定组连通分量划分，整批如园很可能是一个分量。写明即可。

**【轻】2.10 §7 S2 远景措辞自相矛盾。** “只含本分区页的片段”与“其他分区显示最近一次完整取得的内容”不能同时成立：客户端按整区域替换（`客/Voxel/Net/VoxelRegionFetcher.cpp:81` `ReplaceOwnedRegion`）。可行的 S2 定义：远景区域载荷 = 本分区页的在线值 + 他分区页**在 PG 中的最新已发布版本**（只读、不影响写结果，§3.1 读取规则允许），陈旧度 ≤ 他流切点间隔。

## 6. 结论

**可作为第二阶段方向稿批准**：方向、两条硬约束（绑定组不跨分区、岛闭合）、唯一跨界协议及其持久状态机、每流持久化与导入基线、顺序合同改动面、远景事实与 D5 限定，均已由两份首轮评审交叉覆盖且 v2 吸收无反向。批准前最少改 5 条：

1. **【中】稿 §4.5 / §5g（2.5）**：分区退役先迁走全部 owner 行（含离线 cid）；无活化身且已发布干净的分区可免 prepare 翻转。
2. **【中】稿:136（2.2）**：在飞投射物 / 拟态为流级数据随 T2 整体迁移，落地后才归页。
3. **【中】稿 §4.1（2.3、2.4、2.8）**：owner 行物化规则（控制面或 `ON CONFLICT DO NOTHING` 基础网格值）、页键规范加锁序或单条 UPDATE、`deadlock_detected` 可重试不算僵尸、先登记化身再读快照。
4. **【中】D3（2.6、2.7）**：补“被迁岛玩家 T2 期间不可编辑、物理停”与 T1 前置距离参数，再交用户。
5. **【中】D7（§5）**：推荐改为 A（保留 x/z · Y 不限语义 + 控制面登记 + 分片只读投影），B 作为用户主动选择“有界地块”时的备选；并把 Q1(c) 检查对象细化列入决策表。

其余（2.9、2.10、§3 表中的 Replica / baseline / 首切点按页解除、§10.2 / 10.3 / 10.8）随 S2 / S3 落实，不阻断批准。
