# Voxim M3：玩家并发边界与规模验证

状态：**2026-09-09 A/B/C 并发增量完成；只读碰撞、每玩家 Player、独立 Replication 与 Gate 公平合包已部署实跑，200 人 RTT180±10 ms 档达到本轮最低门槛。无延迟对照三项端点缺证及原规模矩阵仍待收口，完整 M3 尚未验收。** 实测唯一维护在 [当前记录](../../../../Voxim/Docs/M3/acceptance.md)。M1 / M2a 的既有验收不变。

完整设计、任务、依据和通过标准统一维护在 [Voxim M3 计划](../../../../Voxim/Docs/M3/plan.md)，下一会话入口为 [接力说明](../../../../Voxim/Docs/M3/next-session.md)，整体阶段见 [Movement-Sync](../../../../Voxim/Docs/Movement-Sync.md)。本页只列服务端归属，避免复制第二套协议和验收标准。

## 本次决策

- 每玩家一个 `SceneServer.Movement.Player` GenServer，独占该玩家输入、运动状态、模拟进度和 ACK 前缀。Gate 入场绑定后直接投递该 owner，Scene 不集中转发所有逐输入消息。
- Scene 保留公共时间、成员与碰撞版本发布；区域的唯一 authority 不等于所有玩家同进程。Player 在已发布时间线内独立推进，不等所有玩家完成同一帧。
- 现有 NIF `Mutex<World>` 与 `CollisionUpdates.at_tick` 原地切历史版必须一起处理。采用按生效 tick/revision 发布的只读碰撞资源；共享查询句柄，不逐玩家复制全世界，不以换 RwLock 代替历史版本正确性。
- 常态去掉逐输入 INFO 生成／输出，保留低频可观测面和必要错误；AOI 消费带真实模拟时刻的不可变状态，由四个 worker 分别拥有观察者关系。Gate 多记录合包沿用现有 codec，替换待发实体时保留 FIFO 次序，避免低 ID 每轮重新插队。

## 修改落点与集成顺序

主要文件为 `apps/scene_server/lib/scene_server/movement/{scene,collision_updates,input_slots,aoi}.ex`、新增实际 Player／复制 owner、`scene_server/application.ex`、`native/voxim_movement_nif/src/lib.rs`，以及 Gate `transport/quic_listener.ex`、`session/{quic_connection,sink}.ex`。共享内核在 Voxim `Plugins/VoximMovement/Native`；正式部署必须包含新增模块和 NIF，不能只热编译旧 Scene 文件。

按主计划 A→B→C→D 推进：只读碰撞版本先接回真实双人编辑；每玩家 owner 先双人再 20 人；AOI／发送改造后复测一个 UE + 199 CLI，RTT180±10 ms、60 Hz 输入、8 秒长段；保留原 100 / 300 / 1000 人后续矩阵。

当前约束：canonical Y-up／米、真实连续输入、精确历史碰撞、现有 Session/Movement/Voxel codec 和 epoch 隔离保持。旧 `worker/player_character.ex` 仅参考按玩家组织的生命周期，不搬旧积分／坐标／NPC/战斗依赖。跨节点移交、故障接管、角色互推不进入本切片。

规划前服务端源码基线 `9bbd825e`，Voxim `a4fe474`；本次实际实施起点分别为 `d6425bcf`、`6f49d50`，分支 `work/m1-overnight-20260908`。最新 Gate 公平替换部署保留 canonical N33，重启后 collision revision 1，日志 INFO。运行中的人数、配置与网络以实验 manifest 为准；保留数据库／编辑，不把历史接力页状态当当前现场。

阶段声明分别记录“增量实现”“真实实跑”“对应人数验收”。首个双人／20 人增量不要求先通过千人或紧性能指标；200 人稳定实时推进仍须实测，不能仅凭 CLI 在线、进程数或单测通过声明成功。
