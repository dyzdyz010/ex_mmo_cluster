## 附件独立损伤增量（实施中，未验收）

依据既有 B1 `Damage` / `property_state` / `PropertyObservation` / World 同步日志实现，复用独立身份、服务端射程和遮挡裁决、GCRA 攻击节奏与窗口观察。附件采用 granularity=3，incarnation 与 owner.birth 是附件 ID，owner.occurrence 是 kind*3+axis；坐标是命中槽。状态键为附件 ID，不与宿主或叶子 occurrence 共用。`0x7D` 尾部增加 granularity:u8，因此两端 Hello=3，旧1/2拒绝；VXR8事实及旧存档余额不变，已有附件首次按现存槽数量产生满血观察，绝不重置已有世界。

一个附件共用 HP；部分支撑失效保留 ID 和剩余部分健康比例，最大HP随实际剩余用量同比减少；裁掉槽只结算一次，显式回收/破坏仅回收尚存槽。无支撑、删除、损坏在同一世界事务移除身份状态与槽；旧ID请求和旧属性观察不能作用于原位新附件。测试覆盖独立目标/宿主不受伤、部分裁剪、旧请求、完整删除、日志失败及checkpoint恢复；先跑双端攻击→扣血互见→破坏→恢复。正式物理规格后续同一增量主线接入，不将当前每槽单位宣称为最终配方。

## Prefab 初始附件与结算（实施中）

依据当前 `Prefab.publish/occurrences` 的不可变发布DAG、A0整数旋转和 `OverlayLog` 同步事务源码扩展，不新增另一套内容目录或附件世界。VXPD v2追加初始附件组（定义内slot、种类、轴、整数锚点、规格尺寸、材料）；无直接附件的v1字节与既有发布SHA不变。发布验证整树槽唯一且得到定义内实体支撑，旋转以几何端点变换处理无向面／棱，不能把体积格三轴-1偏移套给它们。

World 首次放置将附件绑定到该树的preorder occurrence和定义内slot，此后以实际槽、损伤、删除为准。独立uint64附件ID用持久化单调水位分配，同笔多附件不再假定ID等于事务seq。部分裁剪保留ID与归属；显式拆解／替换occurrence移除它自带的实际剩余附件，即使还有外部共享支撑，也不遗留该组件部件；事后加在宿主上的普通附件仍按相邻支撑存活。归属映射与分配水位在World及同一日志／checkpoint中保存，网络槽副本仍引用全局ID。旧测试存档从现有事务seq初始化水位、归属为空，不重建模板或重置槽／余额。

玩家Prefab请求继续经Gate鉴权与既有builder权限入口，World重新验证会话并复用B2请求序列／重复结果。放置／替换／拆解在支撑裁剪后按实际体素与附件前后差额一次结算；允许本次回收支付替换，不按原始模板退款。旧管理API继续只用于测试夹具。存档元数据与Prefab付费语义扩展对应两端Hello=4，拒绝1/2/3；B4单独更新，不热加载到B3运行世界。全阶段验收尚未完成。
