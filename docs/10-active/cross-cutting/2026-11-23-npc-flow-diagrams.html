0　一页看懂：两套东西，一个在跑，一个已定

现行 · 在跑　"npc" 统一形态

进青岚上线用的就是它（deploy/npc/qinglan/register.exs）。一条控制链，慢层给快层提供上下文：

  • 规划：LLM（DeepSeek）写日计划、推进任务、写反思日记，都在 Life 里、稀疏地跑
  • 选择：活动结束时，Jev 从代码生成的候选（Offers）里取第一名
  • 执行：行为树 Trees.npc + 技能，逐步交给 Body，由权威裁决
  • 心智：Life（情绪、关系、人格卡、近期经历）+ Hindsight（记忆与认识），发问时现读拼成心智快照

已定 · 未实施　通用心智（从平地重设计）

用户 2026-11-21 定方向、11-22/23 补充 U-10 ~ U-13。现在在 M-2c（隔离 probe，不改 apps/），不进本次上线，将来原地替换 "npc" 内部。

  • 世界原子是唯一真值；“会做什么”是角色自己写的经验（带参数的树），可错可改
  • Jev 只从角色自己写的条目里挑，并做“要不要停下想”的叫醒判断
  • 进 LLM 思考只有三条路：叫醒判断说停 / 待办表空 / 入睡整合
  • 代码只给事实，主观判断只由 Jev 与 LLM 做

读图提示：第 2–6 节是现在运行时真实发生的流程；第 7–10 节是将来要换成的样子。两者共用的底座（Body、世界权威、Abilities、技能、Hindsight、Jev 客户端、Life 的情绪与人格）在第 10 节的对照表里标为“保留”。

1　NPC 在集群里的位置

NPC 是服务端里的一个“玩家”：它的身体 Body 走和玩家完全相同的意图入口，世界真值仍只在 Scene / World。决策侧只能看观察、发命令、读只读查询，所有出站 HTTP（模型、Hindsight）都经 NpcServer.Http 这一个出口。

铁律：世界真值只在权威侧；记忆与认识只是“我记得”；NPC 的动作失败由权威回 rejected + 原因，不在 NPC 侧伪造成功。

2　现行　分层与时间尺度

一个 NPC 只有一种形态。慢层给快层上下文，快层把经历和例外交给慢层；慢层从不阻塞快层——任何一层在等更慢的层时，都有“继续现在这样”可做。

位置谁坐在这里回答什么问题多快 / 多久跑一次管多长的事
规划LLM（DeepSeek，经 Life 的写作接口）今天想做成什么；任务的下一步；回头看写日记3–30 秒；稀疏（日计划每天 ≤ 2 次、任务推进间隔 ≥ 3 分钟）一个游戏日及以上
选择Selector（位置）+ Jev（判断者）现在做哪件事（含要不要放下手头的事）Jev ≈ 0.6 秒；连同并行召回 2–4 秒；活动结束 / 连续失败 / 被直呼时问几十秒到几十分钟
执行行为树 Trees.npc + 技能这件事的下一步怎么做每 tick，无模型；要台词 / 房屋设计的那一步 3–30 秒几秒到几分钟
权威Body、Scene、World这个动作成不成立每 tick一步
心智Life：情绪、关系、人格卡、未封存近期经历我什么心情、我是什么样的人、刚才发生了什么每个权威事件即时；情绪半衰期 120 秒分钟到小时；人格以天计
记忆Hindsight我经历过什么、我怎么看这些事召回 1–3 秒；写入与巩固后台 10–60 秒；认识满 600 秒才刷新整个一生

“位置”和“判断者”是两个维度：能算的归代码（可行性过滤、紧急避险），封闭但要综合判断的归 Jev，答案开放的归 LLM（台词、房屋设计是某项活动里的一步，由那个技能去问 LLM）。

3　现行　一个 NPC 内部的模块关系

每个 NPC 一个 Runtime，组合 Body 与大脑。Abilities 是决策侧唯一的能力定义，行为树与候选生成都从它取。

登记表里还有 settler / llm / life / patrol 等旧形态，生产登记只用 "npc"，这里不画它们（新设计迁移后它们退役，见第 10 节）。

4　现行　活动选择：一次“现在做什么”

选择本身是树根的一步命令，走现成的 act → Runtime → Outcome 通道：异步、带命令号、过期应答丢弃。身体在等 Jev 时不被锁住。

5　现行　对话回合：边聊边干

玩家直接对 NPC 说话时，Runtime 另起一个回合；当前技能的步骤照常投给 Body，不等回合。一次只有一个回合在途，回合中再来的话只记日志，但照样进经历。

6　现行　经历怎样往上走：Life 与后台慢层

向下是上下文，向上是经历。经历只认权威来源；四段记忆首尾相接：眼前（秒）→ 近期经历与情绪（分钟到小时）→ 召回与认识（小时到天）→ 人格（天）。

SpendBudget 到线时只停后台（认识刷新、反思、日计划等）；写入经历、读认识、选择、说话、召回照常。日计划回顾与任务推进共用一个规划槽，反思有自己的槽。

7　已定 · 未实施　新设计：通用心智闭环

下行是心智（各区 → 推送 → 挑选 → 执行 → 权威），上行是事实（结局、查询摘要、新事件写成经历，同时交给叫醒判断）。思考不碰执行：思考里只能改自己的记忆、做只读查询和 say，其余世界动作要先排进待办，再由挑选与执行器去做。

进 LLM 思考只有三条路（之外没有任何代码会开思考）

1叫醒判断说“停下想”

每个执行结局、挑中没写方式的条目、每个新世界事件（含睡着时）之后，Jev 在完整心智上二选一。挑选里不再有固定的 think_it_over 选项。

2待办表空 → 规划思考

挑选前，此刻没有落在时段里的日程、也没有已到“不早于”的未关待办，系统就直接开一次思考。只看有没有，不看内容；排什么由思考决定，代码不替角色填条目。

3入睡 → 睡眠整合

角色自己排的睡眠条目被执行时开一次整合：只改记忆的组织（写认识、写 / 废经验），不排日程、不行动、不查询。

几个关键名词

世界原子Abilities 的一个条目（动作或只读查询），角色唯一可确信的真理。长技能（gather、build、travel）对心智来说也是原子：发出去，等一个终态。
经验角色自己持有的、由原子组成的树，像带参数描述的函数（名字、意图、参数、树），附使用统计（completed / failed / interrupted 分开计）。醒着能写、改、废；睡眠时整合。
条目与方式条目 = 一项日程或待办，只写“做什么 + 用哪条经验”，不带实参；方式可以是一条经验、一个原子、sleep_until，或空（想做但还不知道怎么做）。
心智原子思考时改写自己记忆的操作：write_journal、set_schedule、add_todo、close_todo、write_experience、retire_experience；每种一份严格格式。
推 / 拉关于自己、有上界、几乎每次都用得上的推进提示词（身份、身体、背包、此刻、各区）；无界的内容思考时拉（召回、目录、地形格子）。
代码只给事实代码只做四件事：转述权威事实、原样转交角色自己写的东西、接纳处格式校验、资源上限。不把 05:42 写成“早上”，不替角色关条目，不借上限替角色决定停下。

8　已定 · 未实施　新设计：谁拥有什么

产品真值（代码，唯一确信）

  • Abilities 条目：原子的名字、参数规格、done 含义、英文说明
  • prepare：运行时限制（范围、格数、射程）与具体原因码
  • 结果投影：查询结果给模型看的样子，由各查询原子的 owner 定义（如 Perception.project），不另行截断
  • Body / World：世界状态与裁决，现查，不存进记忆当真值

角色记忆（数据，可错可改）

  • 类型化存储（Life 持久行）：日程、待办、经验与统计、条目的“上次运行”结局——是 Jev 选项与执行器的真值，要精确
  • Hindsight：经历、日记、认识——要按问题召回
  • Life：情绪、关系、人格卡、未封存尾部
  • 启动数据：登记时写入一次的通用经验库 G0 + 场地起始知识，写进去就归角色

判断者（只有它们做主观判断）

  • Jev：挑选（现在做哪条）、叫醒（要不要停下想）
  • DeepSeek：叫醒后的思考、规划思考、睡眠整合、给经验绑定实参
  • 输出一律经接纳边界校验一次再写进记忆

9　已定 · 未实施　新设计：睡眠与整合

作息由角色自己排：睡眠就是一条普通条目，方式写 sleep_until，几点睡几点起都由思考写、由 Jev 挑；代码不规定必须睡。

  • 整合的不变量：经历原文不可改（整合前后逐字相同）；认识是派生物，只由整合写；经验改写或废弃前旧版本记日志；整合不写日记。
  • 产品化时：Hindsight 白天关自动巩固，入睡时巩固 + 刷新认识（现行 "npc" 照旧，不提前改）。“认识”的唯一写者 M-2c 之后定。

10　旧部件去向与迁移次序

现有部件去向在新设计里
Abilities 与各域模块（Actions、Perception、Dialogue、Skills）保留·加厚成为世界原子契约的唯一 owner；补英文说明、结果投影、结果形状声明
Perception.prepare / project保留·加厚prepare 补原因码；投影补到全部查询原子
技能 build / gather / travel / expand / design_house保留作为长动作原子；design_house 内部问模型的部分暂不动
Body、Runtime 命令通道、Brain.Tree保留Brain.Tree 作经验树的唯一执行器；Body / Perception 加“睡着”状态
Jev 客户端保留Selector 的一次问法拆成“挑选”与“叫醒”两问，选项改从角色自己的条目来
Life：情绪、关系、人格卡、未封存尾部、Hindsight 适配器保留Hindsight mission 与自我认识问句改成与职业无关；巩固改到入睡
SpendBudget保留思考会话花费的唯一 owner
Mind.snapshot 等四处心智渲染合一一个各区渲染器，Jev 与 LLM 共用
三种模型客户端（Writer、Responses、Jev 的 openai 入口）合一思考用一个 DeepSeek 严格工具调用客户端；其余随调用方退役
Runtime 的 choose_activity / 预选 / 对话回合退役由心智闭环替代
Trees.npc、Offers 生成器、计划词表、覆盖登记退役能做什么来自经验，不来自代码
Life 的日计划、任务推进、反思退役由心智原子 + 三条进思考的路取代（规划思考接“每天排计划”，睡眠整合接“整理记忆”）
Trees.settler、Brain.Patrol / Social / Llm、Life.Appraisal；登记名 llm / life退役行为已转写进启动经验库 G0；Brain.Routine 可留作测试替身

迁移次序（当前在第 1 步）

  1. M-2c probe只改 harness 与桥，不动 apps/；进行中
  2. 产品契约原子英文说明、原因码、结果投影、“睡着”状态；无行为变化
  3. 心智核心类型化存储、接纳边界、树编译、思考 / 整合会话、Jev 两问、渲染器
  4. 接入唯一生产根原地替换 "npc" 内部，不另开正式登记名
  5. 退役旧形态根级 readiness / CLI 联合验证通过之后一次退役
  6. 文档同步总纲、current-truth、npc_server README 瘦身
