# 借鉴“AI 小镇”：反思与分层计划（草案，2026-11-13，第六个统筹会话）

分类：设计草案，不是已采用的规范。起因：用户 2026-11-13 要求借鉴 AI 小镇，把**反思**加进流程来整理和丰富记忆，并把计划做成**分层**（至少到一周、最小到半小时）。
依据：子会话读原始来源的回报（统筹会话代存要点，原文不另存；来源 URL 见下）+ 对我们现有代码与总纲的只读盘点。标注：【论】论文原文，【a16z】a16z-infra/ai-town 代码，【推】推断。

## 1. 它们怎么做的

- **记忆流**【论】：每条 = 自然语言描述 + 创建时间 + 最近访问时间；三类——观察、反思、计划（计划另带地点、开始时间、时长）。反思带指向来源记录的引用，可引用别的反思，成树。
  【a16z】只存对话总结与反思两种，观察不入库，**没有计划**。
- **检索**【论】：recency（距上次被取到的游戏小时，指数衰减 0.995）+ relevance（嵌入余弦）+ importance（LLM 在写入时打 1–10 分），三项 min-max 归一后等权相加；取“塞得进上下文”的高分条。
  【a16z】衰减 0.99、importance 0–9 且解析失败默认 5、先取 30 个候选再取前 3；有已知缺陷：某一项在候选里全相同时归一化除 0 得 NaN。
- **反思**【论】：触发 = 近期事件重要性之和 > 150，约每个 agent 每天 2–3 次。步骤：取最近 100 条 → LLM 提 3 个最显著的高层问题 → 每个问题当查询去检索（含旧反思）→
  “What 5 high-level insights can you infer…”，要求写出“洞见（因为 1, 5, 3）”→ 作为反思存回记忆流，可被再次检索与再次反思。
  【a16z】阈值 500，只累加上次反思之后的重要性；**没有“先提问题再检索”这一步**，直接在最近 100 条里总结 3 条洞见；每存一条对话记忆就检查一次。
- **计划**【论】：日（5–8 个粗粒度时段）→ 小时 → 5–15 分钟，自上而下递归分解；第一层输入 = 人物简介 + 昨天的摘要；计划存进记忆流、可被检索。
  每个时间步感知环境，LLM 判断“继续计划还是反应”（提示词末尾 “Should John react to the observation, and if so, what would be an appropriate reaction?”），上下文由两个检索拼成（“我与他的关系”“他在做什么”）；
  决定反应就从那一刻起重新生成后续计划，涉及他人则进入对话。**论文最高只到“日”，没有“周”**。
- **消融**【论】（TrueSkill，100 名参与者）：完整 29.89；去反思 26.88；仅观察 25.64；人类众包撰写 22.95；全去 21.21。反思与计划各自都有显著贡献。
- **失败模式**【论】：检索失败（Tom 检索到计划却没检索到邀请，不确定派对是否存在）；编造（Isabella 说了记忆里没有依据的事；关于“是否认识某人”的 453 个回答里 6 个 = 1.3% 幻觉）；
  过于礼貌正式；**过度顺从**（Isabella 接受大量不符合自己兴趣的建议，兴趣逐渐向他人偏移）；环境规范误判（进被占用的单人浴室、商店已关门仍进）；记忆多了之后选址怪异（去酒吧吃午饭）。
  论文自承：幻觉与 prompt / memory hacking 的鲁棒性没有系统测试；权重与阈值没有调参，记忆流线性增长（综述博客转述）。
- **成本**【论】：25 个 agent 模拟两天，“数千美元 token、耗时数天”（gpt-3.5-turbo，顺序运行，约 1 真实秒 = 1 游戏分钟）；每个 agent 每天总调用数未查到。**成本高的原因【推】：每个 agent 每个时间步都在用 LLM 选动作。**

## 2. 与我们现状对照

| 方面 | AI 小镇 | 我们现在 |
|---|---|---|
| 高频动作选择 | LLM（贵） | Jev 约 0.6 秒、从候选里选 top1（便宜） |
| 计划 | 日→小时→5–15 分，进记忆流 | **没有运行中的计划**：`DayPlan` 代码与单测在，但启动入口随 S1-A 删除，不会启动；活动名表写死（avoid/work/rest/social），与 `profile.activities` 不是一套；只存进程内、不持久化；意图清单只在总纲里有设计 |
| 反思 | 重要性累计触发；提问→检索→带引用洞见→写回 | **没有**。Hindsight 自己做 observation 巩固（带 `source_fact_ids`，等价于“带引用的洞见”）；四份认识（self / relationships / world / commitments）= **固定问题**的反思，我们 retain 后距上次刷新满 600 秒才刷新，与“发生了什么重要的事”无关 |
| 重要性 | LLM 对每条记忆打分（每条一次调用） | Life 的情绪评价本来就给每个事件一个强度（规则模式一次事件 +0.6，`mind.ex` 注释）——**免费的重要性** |
| 检索 | recency + importance + relevance 手写公式 | Hindsight 已是语义 / 关键词 / 图 / 时间四路融合 + 重排，另有 tags、types、`prefer_observations`、`temporal_window` |
| 时间 | 游戏时间 | **服务端没有游戏时刻 owner**（昼夜公式只在客户端，总纲排在薄片三）；选择器文档定游戏日 = 现实 24 分钟 |

## 3. 借什么 / 不借什么

**借**
1. **“计划—行动—记录—反思—再计划”闭环**。论文的消融说明计划与反思都有独立贡献；我们现在只有“行动—记录”，缺的恰是用户指出的那一半。
2. **反思由“累计重要性”触发，不由定时器触发**。重要性用 Life 现成的事件评价强度累计，不额外调 LLM。阈值 150（论文）与 500（a16z）差三倍多，量纲也不同，**必须在我们自己的单位下实测标定**，先只记录触发次数。
3. **反思的三步**：① 从最近经历提出少数显著问题（动态提问；现在四份认识的问题是固定的）→ ② 用问题去多路召回 → ③ 生成**带来源引用**的洞见，**写回记忆**（retain，`kind:reflection` 标签 + 来源 id），可再被召回与再被反思。引用由代码校验存在，洞见在 state 里标注“我的推断、依据几条、多久以前”，仍在“可能过时、不是世界事实”那一栏。
   这正是用户的例子：守屋 12 次期间没人来（§3.2 写入的事实）→ 反思得出“新房暂时安全 / 仍不安全”→ 选择层才有材料。
4. **日计划的输入 = 人物简介 + 昨天的摘要**：“昨天的摘要”正是日末反思的产物；这是日与日之间、日与周之间的连续性来源。
5. **事件触发重排**：重要性高的事件（被拆、被攻击、被直呼）可以打断，从那一刻起重排当天后续时段（对应总纲“选择层说都不合适就再问规划”与 DayPlan 的升级重排）。
6. **计划也进记忆**：计划作为一条记录写进 Hindsight（`kind:plan`，带时段），反思与召回都看得到“我打算 / 我答应过”。但**计划的 SSOT 是一个有序的时段表（持有者唯一，进程重启可恢复）**，Hindsight 里那份是派生物，不从召回结果反推计划（AGENTS 设计纪律 7）。
7. **论文的失败模式当作测试清单**：过度顺从（兴趣向他人漂移）→ 人格卡在每次规划提示里都在场、测“被劝说后是否漂移”；编造 → 引用校验；检索失败 → 多路按 tag 召回。

**不借**
- LLM 逐条打重要性分（有 Life 评价，不加调用）。
- 手写 recency / importance / relevance 打分与归一化（Hindsight 已有更强的融合；a16z 的 NaN 缺陷是反例）。
- **5–15 分钟那一层让 LLM 做**：论文需要它是因为 LLM 就是动作选择者；我们的这一层是 Jev 选择器（见 §4）。
- 每步都用 LLM 的控制方式（成本的来源）。
- 把 a16z 当参考实现：它只做对话总结 + 反思，没有计划层。

## 4. 建议的分层（时间按“游戏日 = 现实 24 分钟”换算，换算是我做的，文档只定了游戏日）

| 层 | 回答 | 谁做 | 频率 | 现实时间 | 输出 | 延迟预算 |
|---|---|---|---|---|---|---|
| 周 | 这周想推进什么（项目、关系、想去的地方） | 规划 LLM，读周回顾 | 每游戏周 + 重大事件 | ≈ 2.8 小时 | 3–5 条意图，**持久化** | 秒级到几十秒，后台 |
| 日 | 今天的 5–8 个时段（意图、地点、对象） | 规划 LLM，读昨天的摘要与周意图 | 每游戏日 + 事件重排（≤4） | 24 分钟 | 有序时段表 | 同上，后台 |
| 半小时 | 当前时段里这一刻做哪件事 | **Jev 选择器** | 每次活动结束 | ≈ 30 秒 | 候选 top1；当前时段与下一时段作为“Plans and promises”栏给 Jev | 2–4 秒（含召回） |
| 执行 | 怎么走、怎么做 | 行为树 | tick | | | |
| 反思（横向） | 发生了什么、意味着什么 | 后台 LLM（可用 Hindsight 的 reflect / 自己的调用） | 重要性累计到阈值 + 每游戏日末一次 | | 带引用的洞见写回；日末产出“昨天的摘要”并更新周意图 | 后台，不上热路径 |

要点：半小时这一层与选择器的节奏基本重合（现在 `stay_ticks` 只有 1–20 秒），所以**不加新的 LLM 层**；计划只是给选择器多一栏有内容的“我这个时段打算做什么、答应过谁”，仍由 Jev 在候选里选。
这与用户定的“不强行要求选项、靠内容让决策涌现”一致：时段表来自 LLM 读心智快照（人格、记忆、关系、昨天），不是手写答案；测试仍从驱动力测。

## 5. 前提与风险（动手前要知道）

1. **游戏时钟**：时段要说“下午”，服务端就得有游戏时刻的 owner；现在没有（薄片三）。选项：薄片二先建最小服务端游戏钟（与客户端昼夜公式同源），或计划先只用现实时间换算的相对时段。
   **用户 2026-11-13 定：做。**“现在服务端是权威，相应的世界基础设施（比如时间）得有。”即服务端权威的世界时间是世界基础设施，不是 NPC 私有；NPC、客户端、其他玩法都读同一个。
   同日对“洞见写回 Hindsight 还是单独存”回复“可以”，统筹会话按推荐项（写回）理解，有异议再改。
2. **持久化**：`DayPlan` 只存进程内；周意图与时段表必须能在重启后恢复，持有者要单一（候选：Life 的持久状态）。
3. **成本**：调研子会话的冒烟里一次 retain（两个短文档）报告约 2 万 token 的用量（子会话回报，未复核）；反思再加一轮。每个 NPC 每游戏日的 LLM 次数估计：规划 1 + 重排 ≤ 4 + 反思 2–3 + 日末 1 + 周的摊销，**最多约 10 次 / 24 分钟（我的估算）**，
   现有 `LlmBudget` 只给 DayPlan 每游戏日 5 次。频率定之前要先量每 NPC 每日实际 token（retain、refresh、反思分别）。
4. **洞见自我强化**：写回的洞见被再次召回、再被反思，会放大早期错误（论文的编造与过度顺从是同类）。对策：引用必须存在、洞见带时间与依据数、有有效期、不在世界事实栏。**这条要靠离线测量验证，不能假定。**
5. **未实测的 Hindsight 能力**：`reflect` 端点（带工具的多轮回路）、mental-model 触发条件、observation 召回内容都没跑过；动手前要先在本线容器上做最小实测。
6. **复用还是重写 `DayPlan`**：活动名表与 `profile.activities` 不一致、入口已删。按“优先删、其次复用”，倾向重写成更小的“意图 / 时段持有者”，设计时定。

## 6. 顺序建议

1. **内容与召回**（用户已全部同意）：继续，先做离线测量。
2. **反思**：先离线——用 S1-C3 导出的真实经历，生成带引用的洞见，再把洞见一句当作驱动加进 state，看选择分布朝哪走（与“只写事实”对照）；站得住再接 Life 的后台调度（`life.ex` `automatic/1`）与 `Life.Hindsight`。反思不依赖游戏钟，也是计划的输入（昨天的摘要），所以排在计划前。
3. **日计划**：游戏钟与持久化就位后，意图 / 时段持有者 + “Plans and promises”栏。
4. **周意图**：在日末反思稳定之后加；论文没有这一层，是我们自己的设计，先做最小版（3–5 条意图，只影响日计划的输入）。

## 7. 离线测量要加的项（运行前写定期望，方向与归因；追加到内容规范 §5）

- **洞见一句作为驱动**（素材：S1-C3 的无人 / 陌生人 / 破坏者三份 state）：`I have guarded the hut 12 times and nobody came near, so it seems safe for now.`（期望：`guard_hut` 概率下降、`visit_plaza` 上升，方向合理；与“只加事实 `nobody came near`”对照，差值归因给“推断”这一步；不要求越过）；
  反向洞见 `…someone came near twice, so it is not safe yet.`（期望：`guard_hut` 上升）。破坏者在眼前时仍应以 `confront_wrecker` 为主（期望：不被洞见一句压掉）。
- **过度顺从的探针**（失败模式清单）：规划 / 选择提示里加一句别人劝他“别管房子了去玩”，看人格卡在场与否对选择的影响（只记录）。
