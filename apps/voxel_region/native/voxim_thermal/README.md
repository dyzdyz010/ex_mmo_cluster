# 批量热内核

分类：Global system。Rustler 0.37.3 DirtyCpu 接收 World 冻结的节点与接触索引，
返回不可变温度、HP、余能与能量账；不保存世界、不发消息、不写数据库。常驻的只有可丢弃的热域拓扑与提交进行中的节点工作副本（见下）。
新活动种子出现时在当前不超过50 ms的稳定步末返回，让 World 更新六邻域后继续本批剩余步。
普通显热测试以现有 Elixir 单步公式为对照，相变测试以解析热量和 World 事件边界判定。
部署只更新本库，不改变世界生成器身份。

## 相变热账数值契约（2026-09-19）

相变焓消费每个稳定数值步已有的接触、有限源和环境净热量，温度由焓派生；
不能用舍入后的温差逆推焓，也不把残差补进环境账。World 继续独占材质替换和提交，
50ms 相变/前沿事件边界不变。依据
[Goldberg 的浮点运算分析](https://docs.oracle.com/cd/E19957-01/806-3568/ncg_goldberg.html)：
温度加微小增量后再相减会暴露已经丢失的低位，应消除不必要的数值往返。

Test-only 验证使用正常 `cargo test --manifest-path apps/voxel_region/native/voxim_thermal/Cargo.toml`：
纯内核直接构造有限源与相态输入，不启动数据库、World、网络或 UE；
真实冰物性277秒反例按解析输入功率乘时间验焓与供热账，保持 `1e-4 J` 门槛。
跨潜热端点与成对接触守恒用小型确定输入验证；NIF/World接缝复用正常
`mix test --no-start test/thermal_batch_test.exs test/phase_world_test.exs`。
这些检查不替代真实双客户端组合场景与共同窗口性能验收。

本次局部验证：正式 Rust 反例在旧数值路径残差 `-0.000259214663 J`，修复后
`-0.000011557364 J`，原 `1e-4 J` 门槛不变；上述 Cargo 入口3项通过，
Mix 入口42项通过、1项实时场景按既有标签排除。原始日志位于同级 Voxim
`Saved/TestingDesignFix/20260919/heat-fix/`。Windows NIF 已经正常 Rustler 构建；
Linux 部署仍须从本源码重新构建 NIF，不能复用旧 `.so`。

2026-09-17 组合性能修复：`advance` 对新热前沿立即返回；已激活的宏格域在同一0.5秒World提交内保留，批末再按实际温度／燃烧收缩，避免0.01K阈值两侧反复重建接触。数值稳定步长、同步持久化和无状态NIF边界不变；旧`batch`接口继续在双向活动变化时返回。参考SciPy `solve_ivp`的定向事件及PETSc的稀疏结构复用；实测、取舍、原始记录见同级Voxim的`Docs/R7/material-performance.md`。这项变更需匹配World与本NIF一同冷安装。

## 灰体辐射换热（2026-09-24，默认关闭）

`advance/7` 的第 7 个参数 `{半对, 对天空}` 由 World 从环境资产 `emissivity`、`view_range_cells`
派生：暴露面沿外法线看至多 `view_range_cells` 个宏格，首个命中的热节点构成面积 `A/2`、
因子 `ε/(2−ε)` 的半对，互逆两条视线合成等发射率无限平行板公式
`q = σA(T₁⁴−T₂⁴)/(2/ε−1)`；未命中或命中无热容量占用按 `εσA(T_amb⁴−T⁴)` 对天空并记入环境账。
每个半对自身反对称，宏/微格尺寸不同也守恒。依据：Incropera et al., *Fundamentals of Heat and
Mass Transfer*（7th ed.）§13.3 漫灰两表面封闭腔（表 13.3 无限平行板）及灰体对大环境的净辐射
（式 1.7）；把互见面近似为平行板、视距外视作天空是本项目的简化，设计与模型对比
（A 空气节点 / C 线性视线 / S 仅天空 / B 本方案）见同级 Voxim `Docs/R8/Design-decisions.md` §10。
线性环境换热保持原语义；辐射项存在时按段首温度线性化 `4σwT³` 重算稳定步长，
两表为空（`emissivity = 0`）时数值路径与引入辐射前逐位相同（`thermal_radiation_world_test`
用主线 79dde382 逐提交记录的摘要验证）。视线伙伴入候选域但不是种子，只有真实升温越过
容差才按既有前沿规则扩域；编辑落在视线缓存包围盒外扩视距内时整体丢弃视线缓存。

## 逐节点环境温度（2026-09-25，气候区）

`advance/7` 的第 3 个参数可为全局标量或与节点同序同长的列表（节点所在气候区的空气温度）；空气换热、对天空辐射与
活动判据都按节点取值。World 一律传列表；无气候区时列表各项等于全局值，数值与标量版逐位相同。`batch/7` 仍为标量。

## 常驻热域拓扑（2026-09-30）

大火里 World 每个内核步都在 Elixir 重建约 2 万节点的接触编号、边界过滤与辐射项（以元组为键的 map 查找约 0.4 µs／次），
单步约 100 ms，是 World 被热模拟占满的主因。`domain.rs` 把拓扑常驻为 `ResourceArc<Mutex<Domain>>`：World 用整数槽位
标识节点键，只推送变化节点的接触 `{伙伴槽位, 导热, 本端发出?}` 与视线 `{伙伴槽位或 nil, 面积}`（`domain_put`），每轮给出
节点次序（`domain_index`，次序契约见下），`domain_step` 用常驻的边与辐射项、外部节点（拟态、身体）的接触追加其后、外部
辐射项排在前面，再进入与 `advance/7` 相同的校验与演化（`kernel.rs`）。资源只是派生缓存：温度、HP、燃料仍是 World 的属性记录，
工作集丢弃（`ThermalWork.new/0`）即随之释放。依据：Rustler 资源（`ResourceArc`）是 NIF 跨调用保存原生状态的标准方式；
按整数下标的连续数组替代散列查找是数据导向设计的常规做法（Fabian, *Data-Oriented Design*, 2018, ch.2/4）。

次序契约（2026-11-07 改）：内核次序由 World 显式给出，是节点键按 Erlang 项序的次序——`ThermalDomain` 在节点进出节点表时
同步维护一个按键有序的集合（`order`，`:gb_sets`），每轮按它给出槽位列表（`domain_index/3`）；内核下标与发边次序都是这一个次序
（逐节点、逐接触，本端发出且伙伴在集内），辐射项按下标、同一节点内按 `{命中, 面积}` 项序（World 推送前排好），同按键遍历的
`ThermalGeometry.contacts/1` 与 `ThermalRadiation.terms/4`。附件派生节点的宿主接触与暴露面也按附件槽键序累加。
次序按键定义而不按加入历史：热域是可丢弃缓存，同一节点集无论整表重建、增量扩域还是闲置后重建，内核浮点求和次序都必须相同。
此前内核下标取 `Enum.to_list/1`、发边取推导式遍历节点表的次序，依赖 Erlang 未承诺的 map 遍历次序（OTP 29 把超过 32 键的
map 遍历方向整体反转，OTP 27 与 29 的结果因此末位不同）；现已不再依赖，节点集合 ≤32 键时新旧次序相同。
`cargo test` 覆盖换次序后下标与边随之重排、伙伴缺席、移除与灰体系数（期望按 Elixir 规则手算）；Mix 端
`thermal_domain_test.exs` 用 `domain_terms/1` 对照按键次序的参考规则（含 40 节点大表：其 map 遍历次序与键序不同，
内核若按 map 遍历次序编号或发边即失败）。

节点工作副本（同日，2B）：`sim.rs` 在资源里保存每个节点的静态量与动态量（`domain_load` 装入、`domain_reload` 按外部改写重装，
`only_clean` 时跳过尚未写回的节点），`domain_step` 一步内按原 World 顺序执行演化、燃烧（燃料耗尽判据 ε 由调用方给出）、
点燃事件、耐热失血、采掘基线与热源，只回传变化槽位、损失 `(槽位, 前值, HP)` 与事件；`domain_flush` 交出全部待写回节点并清脏标记，
`domain_values` 只读不清。写回与真值归属由 World 决定（服务端 README 2026-09-30 第四项）；`cargo test` 的 7 例规则测试
按原 Elixir 公式手算期望。

## 外部节点限流（2026-11-26，魔法 v2 切片 4b）

魔法结构的热端口是内核外部节点；设计 §5.3.1（TheWorldBook `2026-11-19-glyph-composition-game-design.md`）要求内核在施加热流
**之前**对它限流，使结构的吞吐不超过 Φ_cap、热份额不越过容量（x ≤ 1），并把温度钳在 T_chk = 2500 K 以下（T15 的稳定步长在运行中成立）。
决策稿：`docs/10-active/magic/2026-11-26-p1-closure-slices4-8.md` §4.1、§10、Q4-1、K4-1。

接口：外部节点除原有的 `{输入, 事件}` 与纯 `输入` 外，可写成 `{输入, 事件, {phi_w, t_lo, t_hi}}`（`AdvanceInput::Limited`，
`domain_step/12` 与 `advance/7` 都接受）。不附第三项即不限（Erlang 浮点没有无穷，"缺省"就是 +∞ / −∞ / +∞）；三项须有限、
`phi_w ≥ 0`、`t_lo ≤ t_hi`，否则 `badarg`。世界节点一律不限。`domain_step` 返回元组末尾追加
`{子步数, 吞吐受限节点数, 温度钳制节点数, 最小吞吐缩放比}`（`ThermalDomain.step/11` 的 `kernel` 字段）；计数按一次调用统计。

每个子步（`kernel.rs` 的 `Throttle::factors`）：

```mermaid
flowchart LR
  A["1 按现有公式算出四类热流<br/>接触 / 互见 / 对天空 / 对流（只算）"] --> B["2 吞吐 s_i = min(1, Φ·dt / Σ|q|)"]
  B --> C["3 边取两端 s 的较小者<br/>对天空、对流取 s_i"]
  C --> D["4 试算温度越过 t_hi（t_lo）：<br/>流入（流出）各项乘同一 k，恰好到边界；<br/>边取两端 k 的较小者"]
  D --> E["5 两端等量施加（守恒）"]
```

- 有限源（功率与余能）不属于四类热流，不缩放，试算时按原样计入。
- 节点已高于 t_hi（拍间储能变化使上限下移）时 k = 0：流入全部挡住，流出照常。
- 稳定步长的计算不变（缩放只减小热流）；温度钳制让辐射线性化系数在 t_hi 处有上界，所以 T15 的"每 50 ms 段至多 2 个子步"在运行中成立。

逐位不变：各项热流先写入缓冲、再乘系数施加；不触及受限节点的项系数恒为 1.0，乘 1.0 在 IEEE 754 下精确，
求和次序与原实现相同。证据：`kernel::tests::unlimited_nodes_reproduce_the_pre_throttle_kernel_bit_for_bit` 冻结了改动前内核
（`1e6afc56`）对同一样本三条路径（整段推进、热前沿提前返回、旧 `batch` 定步长）的输出位模式；
`limits_that_never_bind_…` 证明参数不生效时受限节点同样逐位不变。

依据：骨架对照 Zalesak FCT 限制器（J. Comput. Phys. 31:335–362, 1979）——节点约束求比例、每条边取两端较小者、保持守恒；
约束换成吞吐与温度上下限是设计的原创决策（设计 §13.1、决策稿 §10）。

已知边界（待设计确认）：两个受限节点直接相连的边上，按设计"取两端 k 的较小者"后，未被钳制的一端可能因对端缩小而略越过自身边界；
当前几何里结构只与世界节点、身体节点相连，不出现这种边。

Test-only 验证：`cargo test`（`voxim_thermal`，含上述逐位对照、吞吐两侧收付一致、上下限恰好停在边界、两端受限取较小、
四类热流守恒、T15 最小热容热球的子步上界与边界校验）；Mix 端 `test/thermal_native_test.exs` 经 `ThermalDomain.step/11` 验参数与计数。
